# 首次安装引导：技术核查与逐页 UI 方案

日期：2026-10-27

状态：T01–T12 功能已实现；T13 开发态自动化与报告已完成，真实服务、真机与当前发行包仍未验收。SEC-01 凭据明文存储已按用户决定接受为非阻断风险，本轮不扩展加密迁移。实施证据见开发计划第 12 节及 [T13 验收报告](../qa/2026-10-27-first-run-onboarding-acceptance.md)。

术语（2026-10-27 调整）：首次使用引导统一称“初始设置”，汇总页为“设置检查”，恢复入口为“继续设置”。原“会议准备”功能仍指具体会议的上下文与材料准备，不改名、不迁移数据。

范围：首次安装引导及其涉及的首页、现有会议界面；不重新设计应用全部设置页面。

## 1. 已确认目标与方案边界

用一条主线帮助新用户完成必要配置，并启动第一次真实会议：

**欢迎 → 设置概览 → 权限与设备 → 语音识别 → AI 服务 → 开始会议 → 现有会议界面。**

- 集中式分步引导；已有账号/密钥与零准备用户都覆盖。
- 无凭据用户按指引开通现有服务；不新增试用额度、计费或账号系统。
- 最后一步使用现有开始会议流程。**不新增试用页面、模拟问答、测试会议或另一套录音流程。**
- 引导允许退出和恢复，关闭、跳过、点击开始均不等于成功。
- 画像、资料库、Embedding、自定义模式、专名词表等不作为首次会议的前置项。
- 首次会议继续使用既有模式选择与默认值，不在引导里强制选择销售/FDE/通用模式。
- 本文中的新增接口、状态与组件均是后续实现要求，不代表代码已经具备。

### 本轮采用的设计默认值

这些是基于当前代码的设计选择，不是额外声称已经得到用户逐项确认：

1. 面向中文会议使用；全新且未配置用户推荐 SenseVoice 本地转写 + 豆包 AI。语言选择保留现有语言列表与兼容性检查，不宣称覆盖所有语言。
2. 已有配置优先展示和验证，不自动改写 provider、模型、设备或数据范围选择。不存在可用配置时才推荐默认路径，用户点击后才保存。
3. 新用户的主路径提供本地 SenseVoice、现有 Doubao AUC 云端转写；已有 QCLOUD 配置时展示对应选项。已有 Whisper 或其他历史 provider 保留原值，使用对应现有设置表单与检测适配，不强制迁移。
4. AI 主路径提供豆包与 QCLOUD API；QCLOUD 服务与模型使用用户可读名称，内部旧标识保持兼容。已配置的 Codex、其他云端或本地服务保留当前配置。其他服务通过集中引导内的“使用其他服务”面板复用现有配置，不另造服务注册系统。
5. 缺少系统音频授权时允许明确选择“了解限制，继续设置”，沿用现有会议降级行为；不是新增强制关闭系统音频的模式。标注“受限”，不显示“所有功能已就绪”。

## 2. 技术核查结论

本轮使用知识图谱定位后读取源代码。未运行真实安装、授权、下载、账号登录或付费请求；以下属于静态核查，不能替代发行包验收。

| 核查项 | 代码事实与证据 | 对方案的约束 |
|---|---|---|
| 欢迎页与首次状态 | [App](../../src/App.tsx) 用 `natively_seen_startup_v1` 控制欢迎页；[StartupSequence](../../src/components/StartupSequence.tsx) 的继续按钮只调用完成回调 | 欢迎之后接准备流程；旧“看过”标记不能推导配置就绪 |
| 分散提示 | [Launcher](../../src/components/Launcher.tsx) 分别管理模式与画像提示；[PermissionsToaster](../../src/components/onboarding/PermissionsToaster.tsx) 关闭即写已展示标记 | 首次引导期间统一抑制这些提示，避免重叠；保留手动功能入口 |
| 初始 STT | [CredentialsManager](../../electron/services/CredentialsManager.ts) 的未配置默认值是 `none`；部分历史配置才迁移到 SenseVoice | 不能假设全新安装已经选好本地转写；引导必须显式选择并保存 |
| 权限检查深度 | [IPC](../../electron/ipcHandlers.ts) 的 `permissions:check` 使用 `probeScreenSources: false`；[权限健康检查](../../electron/permissions/macPermissionHealth.ts) 此时主要依据系统状态，非 macOS/开发环境还有直接通过分支 | 自动检查只能称“已授权/待实际使用确认”，不能声称真实捕获成功；发行包真实权限测试必需 |
| 系统音频 | [main.startMeetingInternal](../../electron/main.ts) 保留麦克风授权；系统音频由原生后端在实际开始采集时检查，失败独立提示 | CoreAudio Tap 与 SCK 的权限路径不同，不能用屏幕枚举结果阻断所有系统音频；截图独立检查授权 |
| 设备与电平 | [preload](../../electron/preload.ts) 已有 `getInputDevices/getOutputDevices`、`startAudioTest/stopAudioTest/onAudioTestLevel` | 可复用已有麦克风电平检测；无须新增录音测试功能；系统音频不能借麦克风电平冒充验证 |
| SenseVoice 文件状态 | [modelManager](../../electron/audio/sensevoice/modelManager.ts) 目录标注约 250 MB，available 依据模型与 tokens 文件存在 | 大小从目录读取；文件齐全不等于运行时加载成功 |
| 下载与恢复 | IPC 有下载开始、进度、完成、错误；进度发送给发起的 renderer；查询模型目录不包含完整下载任务状态 | 同窗切页保持订阅；重载需补可查询的活动任务状态；不承诺现有下载器具备暂停或断点续传 |
| 预加载 | `local-sensevoice-preload` 仅检查缓存并安排预加载；Whisper 返回也不是 await 完整加载 | “预加载成功”不能直接显示“语音已就绪”；需读取/等待真实 worker ready 或明确显示待验证 |
| AI 测试 | `test-llm-connection` 可从主进程读取已保存密钥，但测试模型部分固定；`test-codex-cli` 只调用 [validateExecutable](../../electron/services/CodexCliService.ts) 的 `--version` | 固定模型测试不证明选中模型可用；Codex 存在不证明登录或推理成功；最终验证需走实际选中配置 |
| 凭据与范围 | `setDoubaoLlmApiKey` 和 STT 的 `setDoubaoApiKey` 是不同入口；[SettingsManager](../../electron/services/SettingsManager.ts) 保存全局 scope 设置；[ProviderRouter](../../electron/llm/ProviderRouter.ts) 目前以显式 false 拒绝范围 | 不混用 LLM/STT 密钥，不擅自覆写其他 scope；UI 不能虚构每个 provider 独立的授权开关 |
| 会议生命周期 | App → Launcher 回调 → `start-meeting` → main；`isActive=true`、`phase=ready` 在异步音频初始化前发出；部分提前 return 也会使 IPC 返回 success | IPC success/ready 只能表示进入会话，不能表示音频与转写成功；新增引导不得依赖这个假设 |
| 失败反馈 | [NativelyInterface](../../src/components/NativelyInterface.tsx) 监听启动、音频失败、STT 状态；App 当前启动回调只向 Launcher 返回 boolean 并记录错误 | 要保留结构化错误及修复目标，订阅必须早于启动；复用原错误条，不再叠加第二套错误 UI |
| 窗口尺寸 | [WindowHelper](../../electron/WindowHelper.ts) Launcher 默认 1200×800，最小 600×400 | 引导放现有 Launcher；不新增 BrowserWindow；小窗口也必须能操作底部按钮 |

### 已解决的关键歧义

- **准备状态不等于端到端成功。** 授权、文件可用、服务请求成功分别显示；实际捕获与转写在真实会议中确认。
- **本地转写不等于整条链路离线。** AI 若选择云服务，转写文本仍可能发往该服务；Codex 在本机运行也不能标为本地离线推理。
- **屏幕功能权限与系统音频关系按平台解释。** 不要求截图理解作为首次会议验收，但 macOS 的系统授权可能同时决定能否获取对方声音。
- **配置完成、会话进入、收到转写分开。** 配置完成后用户可以稍后开始；进入记录不是音频成功证明，异步失败必须继续显示，真实转写才写转写证据。

## 3. 导航结构与公共视觉规范

### 页面清单

| 编号 | 页面/表面 | 出现条件 |
|---|---|---|
| P0 | 欢迎 | 全新安装；复用现有欢迎内容 |
| P1 | 设置概览 | 首次开始配置、恢复引导或手动检查 |
| P2 | 权限与设备 | 麦克风/设备未准备，或用户主动查看 |
| P3 | 语音识别 | STT 未配置、模型缺失、验证失败，或修改选项 |
| P4 | AI 服务 | AI 未配置、选中模型未验证、范围受限，或修改选项 |
| P4a | 开通服务说明 | P4 选择“我还没有账号或密钥”；嵌套子页，不新增主步骤 |
| P5 | 准备完成 / 开始会议 | 必需项可用，或明确接受系统音频受限 |
| P6 | 首页继续设置卡片 | 用户退出或既有用户存在待处理项 |
| P7 | 现有会议界面首次提示 | 从现有流程进入真实会议 |

P0 → P1 → P2 → P3 → P4 → P5 → P7；P4a 返回 P4。P1–P5 的“稍后继续”返回 P6；P0 关闭遵循窗口原行为。P6 从首个未完成项恢复。已满足条件的步骤自动跳过，但可从左侧导航回看。

### 统一通行规则（所有页面与开始入口共用）

| 状态 | 页面行为 | 首次会议入口 |
|---|---|---|
| 麦克风明确拒绝、无可选输入设备、STT=none/文件缺失/验证失败 | 对应步骤待处理或失败 | fresh 用户回 P2/P3；未知状态不能伪装成拒绝，也不能标绿 |
| AI 缺凭据/配置验证失败、transcript 明确拒绝 | P4 说明阻塞原因，可稍后退出 | fresh 用户回 P4；本期不新增“只做转写”绕行模式 |
| 系统音频明确未授权 | P2 要求知情选择；P5 警示可能缺对方声音 | 接受当前限制后可继续，绝不表示禁用系统音轨 |
| 被动检查通过、实际捕获只能在会议确认 | 展示“待会议确认”，不是检查失败 | 可继续；Windows 的此状态不造成无法开始的循环 |
| 配置未变且有有效历史验证回执 | 显示“上次验证通过”，附时间 | 可以开始；不因重启强制复测 |
| 运行中下载/验证、未保存字段 | 可访问其他配置步骤，P5 只展示待完成摘要 | 未完成前不可启动；不自动保存或跳过未保存字段 |
| existing 用户或已有活动会议 | 保留原产品行为，手动检查失败如实显示 | existing 不受新引导拦截；活动会议直接返回原 overlay |

“配置完成”要求 P2 必需项满足、P3 与 P4 验证回执匹配已保存配置、相关 scope 允许，且系统音频限制已处理或知情接受。受限状态在摘要单独展示；配置完成不是音频捕获保证。首次门禁仅适用于 origin=fresh 且 configurationCompletedAt 为空的用户，完成引导后不永久锁住后续会议；P5 手动进入仍检查当前已知阻塞。所有需门禁的开始入口在现有 start-meeting handler 前使用同一判定，不只挡 P5/Launcher 按钮；拒绝时返回 recoveryStep 并定位现有 Launcher，不另建启动路径。活动会议和正在启动的请求先走既有复用/去重逻辑。

### 公共布局

- 复用现有主题变量：`--bg-sidebar`、`--text-primary`、`--accent-primary` 与已有表面/边框 token；支持亮暗主题，不再使用独立硬编码配色。
- 状态统一使用 `--status-{info|success|warning|error}-{text|bg|border}`，由应用 `data-theme` 决定亮暗，页面不再使用固定 palette / `dark:` 状态色。主按钮复用 `--btn-primary-*`，规则与用例见[通用状态颜色](../design/semantic-status-colors.md)。
- P1–P5 使用统一壳：顶部产品名和“稍后继续”，左侧 200 px 步骤栏，右侧最大约 680 px 的内容区；页面内边距 32 px、卡片间距 16 px、卡片内边距 20 px。
- 小于 800 px 隐藏左栏，改用顶部“第 N 步 / 共 5 步 + 当前标题”；内容内边距 20 px。600×400 下只有内容区滚动，页脚始终可达。
- 标题 24 px，正文 14 px，辅助信息 12 px；主按钮与输入框高度至少 40 px；每页只保留一个主要下一步按钮，卡片内验证按钮使用次级样式。
- 步骤状态用图标 + 文字，不只靠颜色：待处理、检查中、已准备、受限、失败。只有可量化的模型下载显示百分比，不伪造总体进度或剩余分钟。
- 页脚统一为左侧“上一步”，右侧主动作；没有未保存字段时退出无需确认。存在未保存字段时使用下述内联离开提示，不另弹层叠模态。
- 系统标题栏拖动区域不覆盖按钮/表单；所有交互控件设置 no-drag。键盘 Tab 顺序、明确焦点样式、表单 label、错误播报和 reduced-motion 均需覆盖。
- 数据读取失败显示“检查失败，重试”，不能用空数组、默认 granted 或未返回字段推断成功。所有“继续”按钮受同一规则控制；禁用时紧邻展示具体原因和可操作的修复按钮。
- 左侧步骤可查看并行配置，尚未满足条件的 P5 只展示待完成摘要，按钮为“继续设置”；不允许导航本身把步骤标为完成。P3 返回时仍显示下载状态。
- 输入变更先标“未保存”，明确按钮“保存并验证/保存并继续”才提交；成功后刷新摘要再跳页。未保存时点击上一步、侧栏或退出，提供内联“保存并离开 / 放弃修改 / 留在本页”；只有用户明确放弃才清空。关闭原生窗口无法保留未保存密钥，输入区常驻说明“未保存内容将在关闭后丢弃”。P4a 入口在有未保存输入时同样遵循此规则。
- 检查只读状态可自动进行；授权申请、下载、云端验证由用户点击触发。页面不自动打开系统设置或外部浏览器。

- 设备列表复用现有设备枚举；默认选择系统默认。已存设备消失时提示重新选择，不能继续显示不存在的设备可用。继续保存到当前 preferredInputDeviceId/preferredOutputDeviceId 路径，空/默认值遵循现有启动约定；不建立第二套独立设备偏好。检查摘要请求和启动请求均携带当前选择，主进程重新枚举比对，不能假设主进程能直接读取 renderer 的 localStorage。
- 现有电平检查会在指定设备失败时回退系统默认，且 start-audio-test 仅返回 success。后续须兼容扩展返回实际 deviceId 与 fallback 标记，并回传已有捕获错误；UI 若回退则显示“当前检查的是系统默认设备”，提供“改用该设备”，未确认前不改写选择，也不把原设备标为已验证。
- “检查电平”复用既有音频测试，仅用户点击后开始；按钮切为“停止检查”。离页、退出、切设备或开始会议前停止测试；不保存音频、不做 STT、不调用 AI。必须在主进程处理授权等待期间退出的竞态：测试请求带 owner/代次，stop 或窗口销毁使其失效，授权返回后不得再创建捕获；开始会议前统一终止未完成电平检测，renderer cleanup 不能作为唯一保障。
- 无波形不立即判失败，提示检查静音或说话；电平检测不是强制要求用户说话的关卡。
- macOS 分别展示麦克风与系统音频状态，打开系统设置后保留本页，窗口重新聚焦时重新读取状态；未触发实际捕获时标注“授权已开启，会议开始时确认”。
- 仅明确的 `denied/restricted` 且无有效授权证据时提示限制；`unknown/not-determined` 显示尚未确认，不误判拒绝。刷新必须显示读取中、完成和失败反馈，重试成功清除旧读取错误；应用读取值与系统设置不一致时明确说明，不能直接宣称用户未授权。
- Windows 不显示 macOS 系统设置链接；只显示设备和“会议开始时确认系统音频”。现有 IPC 的 granted 不作为真机捕获已验证证据。
- 系统音频缺失时，“继续”要求用户先授权或显式点击“了解限制，继续设置”；紧邻按钮说明“未授权时可能只能转写你的声音；开始会议仍会按现有流程尝试系统音频，并可能显示系统授权提示”。这不是关闭音轨的选项，也不承诺只采集麦克风。该知情选择在 P5 重申，授权恢复后清除；其他系统音频错误不能被此标记忽略。

## 5. 状态、恢复与最小接口调整

### 持久化

在现有 SettingsManager 的非敏感 settings 中新增 version=1 的 onboarding 状态；主进程为唯一写入方。持久字段如下（均为非敏感元数据）：

- origin：fresh / existing，首次建立时判断；用于区分新安装引导与旧用户非阻塞迁移。
- lastStep、deferredAt、configurationCompletedAt、firstMeetingEnteredAt、firstTranscriptReceivedAt，以及 meetingHintsDismissed 的 transcript/answer 两个布尔值。
- acceptedSystemAudioLimitation：仅表示用户知道当前授权缺失；授权恢复或平台变化时清除，不表示关闭音轨或忽略其他错误。
- validationReceipts：stt/ai 最近一次验证回执；对应 configRevision 在相关配置写入时更新，后续其他设置入口也必须触发失效。

不存储密钥、转写、测试 prompt 或“永久健康=true”。仅持久化最近一次验证回执：服务/模型标识、非敏感配置 revision、checkedAt、验证深度与结果；不保存凭据哈希或响应正文。运行中任务与当前错误留在内存。重启后回执只能显示“上次验证通过（时间）”，不声称本次已联网验证；配置未变且被动检查没有新失败时允许继续，不因每次重启强制付费复测。凭据/模型/语言/端点或相关 scope 改变时递增对应 revision 并失效相关回执；本地模型额外核对文件版本与应用运行时版本。configurationCompletedAt 是历史，不覆盖实时失败。手动“重新验证”可更新回执；任何已知失败均优先于历史成功。

初始化判定必须发生在 P0 写新欢迎标记之前：先读取既有 onboarding，存在则沿用；否则由主进程读取有意义的已保存配置或非演示会议记录的存在性，renderer 仅提供初始化前的旧欢迎/权限提示标记布尔值（不上传 localStorage 全量内容）。任一旧使用证据存在即判 existing；自动默认值、内置演示数据不算证据；明确无证据才为 fresh，读取失败按 existing 非阻塞处理并提示可手动检查。初始化结果一次持久化，后续导航不重算。legacy 标记仅影响展示，不作为权限或就绪证据。

| `onboarding-state-changed` | 主进程在保存、下载/验证完成、会议进度变更时广播；所有窗口读同一状态；刷新后可主动读取，不依赖恰好收到一次事件 |
| 现有会议状态补充 | 保持 ready 及 connected 的旧语义；仅把会话进入、音频初始化回调、既有错误及真实转写事实写入 onboarding 摘要，不把 connected 提升为健康证据 |

- 所有新 handler 用 safeHandle；同步 preload、renderer 类型声明及共享类型。读状态不能隐式授权、下载、调用云模型或启动音频。广播/快照携带单调 stateRevision；renderer 先订阅再读取，忽略更旧的快照或事件。导航持久化仅允许 Launcher 修改，overlay 只提交提示关闭动作，避免多个窗口争抢 lastStep。
- 复用现有凭据 setter，不设计新的密钥存储接口。豆包 AI 使用 LLM 专用 setter；STT 使用其现有入口。
- 服务验证复用现有连接/推理执行逻辑，并遵循 routeWithScopeFallback/assertProviderDataScopes；固定输入也不得绕过当前明确拒绝的范围策略。调用 AI 验证前在按钮附近说明“会向所选服务发送固定验证文本，可能产生少量费用”；STT 验证提示对应内置样本。没有用户点击不发请求。

- 新的验证只操作当前所选配置，不附加会议上下文、不生成会议记录、不启用工具或附件。主进程从安全存储解析配置，校验请求的 revision；不允许 renderer 提交任意命令、URL、密钥或模型路径绕过现有验证器。所有验证/模型替换在主进程检查 meeting-active、所有者与配置代次，不能只禁用按钮。
- 失败码至少区分：permission_denied、device_missing、model_missing、model_load_failed、credentials_missing、authentication_failed、model_unavailable、network_error、scope_denied、unsupported_check、busy、timeout、stale_config、storage_failed。原始错误经过脱敏再映射，不把响应体和密钥放 UI。
- 结果到达时检查配置版本；用户已更换 provider/model 时丢弃旧结果，不能把新选择错误地标绿。
- 输入密钥更换但未保存时不得后台测试输入；持久设置仍为旧值，UI 明确标示“未保存”。

### 会议进入、转写证据与时序

1. P5 只调用现有开始会议回调；主进程现有 in-flight 保护继续生效。
2. isActive=true / ready 只显示“已进入会议，正在连接音频”。
3. 主进程实际置 isActive=true 时记录 firstMeetingEnteredAt，仅表示进入过真实会话，绝不命名或展示为“音频/转写成功”。IPC 提前返回但未激活会话时不写入；生产状态写入排除测试跳过音频、基准注入及演示会话。
4. 现有音频初始化回调完成只表示已发起捕获，文案为“音频已启动，等待转写”；系统音频已知失败单独提示。首次非空真实转写到达时写 firstTranscriptReceivedAt 并显示“已收到转写”，不存文本；没有讲话不算失败，也不阻塞退出。
5. 不把现有 STT connected 事件作为就绪证据：main 在绑定监听器时就广播 connected，SenseVoice 真正 worker ready 在另一条内部消息中。配置阶段复用已有 worker 加载检查；会议阶段只消费现有启动/错误/转写事件，不另造通用 STT 连接健康框架。
6. 启动代次关联已有 session generation，忽略上一场晚到的结果。异步失败优先显示修复卡；不删除“进入过会话”的历史，但不能显示转写成功。已收到真实转写后发生的故障不抹除历史证据。
7. 历史时间不等于“以后永远可用”；再次开会仍沿用正常错误检测。

### 退出与恢复

- 异步下载保留在主进程；同窗切页保持顶层订阅，重载通过状态快照找回进行中的任务。
- 进度保存失败时明确提示“未能保存进度”，不谎称恢复已保障；不得把密钥临时写入普通配置兜底。
- 本地加载使用既有 60 秒超时；AI 验证上限 60 秒（内部 provider 更短超时仍有效），STT 测试沿用原测试超时但外层最长等待 60 秒。超时显示重试/更换服务，返回 timeout；任务终止前禁止重复启动相同配置。具备 abort/子进程取消能力时取消并清理；不支持时任务保持后台状态并丢弃晚到结果，不把 UI 超时伪装为任务取消。网络型请求不自动重试产生额外调用。
- 关闭引导停止电平检测；取消 UI 等待不宣称已经取消后台任务。晚到结果必须经过配置/会话版本检查。
- 已有会议活动时不启动新的电平检查或切换 STT；提示“会议结束后调整”，保留“返回会议”入口。
- origin=fresh 的 onboarding 接管旧首次提示，直到配置完成或用户稍后退出也不补弹旧 PermissionsToaster/模式/画像提示；必要项由恢复卡承接。高级功能改为手动访问时介绍，不永久标记为已看过。existing 用户仅在打开新引导时抑制旧提示，避免改变其其他既有交互。
