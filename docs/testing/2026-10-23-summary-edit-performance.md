# 摘要编辑卡顿调查与最小修复

日期：2026-10-23（America/Los_Angeles）。本记录随摘要和转录编辑性能修复一并提交；尚未构建新安装包或正式发布。

## 已定位问题

摘要每次输入触发 autosave 草稿通知。原 `snapshot()` 总是复制整场转录及全部片段，导致转录行的 memo 失效；详情页还无条件执行 `formatTranscriptForSkill()`，逐段调用日期格式化、身份解析并拼接整场文本，即使用户正在摘要页也如此。

隔离脚本执行生产 controller、生产详情页实际派生表达式及与React一致的依赖缓存；使用虚构会议，连续8次修改摘要。1000段的同步计算中位数19.120ms、最大28.939ms；5000段中位数102.959ms、最大115.579ms，8次均使转录引用变化。此数据只覆盖上述同步计算链，不包含完整React渲染、输入法或屏幕绘制，不作为端到端键盘延迟。

## 最小修复

仅修改两个生产文件：摘要编辑保持未变转录引用；转录文字草稿采用不可变方式仅复制修改的片段；转录技能文本按页签及转录引用缓存，只在转录页需要时生成。复用原有即时草稿、600ms保存、冲突处理、复制和离页flush。

同一脚本修复后1000段中位数0.017ms、最大0.101ms；5000段中位数0.004ms、最大0.069ms。摘要修改均不再改变转录引用。原始脚本及数值位于本地 `.tmp/summary-edit-performance/`，不提交原始日志。

## 同日续修：转录编辑

用户要求按同一方向最小修复转录编辑。首轮仅把全文格式化限制在转录页，因此转录页每次改字仍会生成整场文本；1000段同步计算中位数19.101ms，5000段108.010ms。

续修在上述基础上，仅调整详情页和转录行：技能入口根据已有可见行判断可用性，不在渲染时生成全文；技能执行先flush，再从最新保存快照格式化。现有复制完整转录仍先flush再生成全文。时间标签按时间戳及格式化函数缓存，文字修改不重复格式化可见行时间。继续复用原有自动保存控制器，不增加保存层或修改600ms保存时机。

同脚本8次改字，修复后1000段中位数0.119ms、最大0.879ms；5000段中位数0.194ms、最大0.706ms。仍有轻量数组映射与转录行投影；没有为消除所有线性遍历引入索引结构。测量仅包含生产控制器和派生计算，不含完整界面绘制。

- 新的性能和技能快照断言在续修前2/2失败；续修后控制器、派生行为、虚拟行及转录行共29/29通过。技能用例执行生产处理函数，验证保存完成后才读取快照、使用最新文字，保存失败不执行技能。
- 隔离Electron针对两份spec定向9/9通过（38.7秒），含5000段连续转录输入、立即复制最新文字及完整尾段、SQLite保存、切页后保留，另有原T5失败重试、虚拟卸载／重开、Word、词对记忆、空白保护，以及摘要编辑保存相关回归。新增界面用例中输入期间日期格式化调用为0。
- Renderer类型检查、E2E自动Electron构建、diffcheck通过；日志见 `.tmp/summary-edit-performance/transcript-*.log`、`transcript-after.jsonl`。未操作真实用户库、录音或外部服务。
