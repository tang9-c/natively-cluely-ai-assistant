# v2.8 启动退出 SIGSEGV 调查

日期：2026-10-17。分支 `codex/v2.8-foundation`，调查基点 `3be4882250ac3d127c289f4f40ed371c0802dce3`。macOS 26.1 / arm64 / Electron 42.6.0。仅修改测试驱动和隔离边界，不修改产品退出流程、不升级依赖。

## 结论与适用范围

T7 历史 SIGSEGV 是调试接口同步执行 `app.quit()`，重入正在构造的原生窗口引起的空 isolate 访问。历史栈、匹配符号、反汇编和确定性最小复现互相吻合。修复为测试退出请求使用 `setImmediate` 进入正常事件循环，让被 inspector 中断的窗口构造栈先返回；没有用固定等待、重试、强退或升级 Electron 掩盖崩溃。

这关闭的是**已捕获的这一条 SIGSEGV 原因**，不代表真实用户所有启动退出故障都已验收，也不代表 Electron 本身的原生缺陷被修复。没有证据支持把该崩溃归因于 TLS、音频采集、本地模型或 v2.8 保存屏障。

## 历史故障证据

匹配系统报告 `Electron-2026-10-17-085159.ips`：PID 11726，启动 08:51:32.8576，故障 08:51:37.6994（-0700），主线程 `CrBrowserMain`，`EXC_BAD_ACCESS / SIGSEGV`，地址 `0x230`。仅读取异常、线程栈、寄存器和模块元数据，不读取会议库、凭据或内存内容。

官方 `electron-v42.6.0-darwin-arm64-symbols.zip` 的 SHA-256 为 `dc02ae59d8a4b087d666a4ca048d037aa15dbbfd2c2545af4c6e47152b9fcd05`，已与官方 SHASUMS256 校验。Breakpad ID `4C4C445F55553144A159C6B0474AA75A0` 与报告 Framework UUID `4c4c445f-5555-3144-a159-c6b0474aa75a` 匹配。

精确符号化后的关键栈（上方为崩溃位置）：

```text
EventEmitter<BaseWindow>::Emit +44
BaseWindow::WillCloseWindow
NativeWindow::NotifyWindowCloseButtonClicked
ElectronNSWindowDelegate windowShouldClose
ElectronNSWindow performClose
WindowList::CloseAllWindows → Browser::Quit
v8_inspector callFunctionOn / Node inspector dispatch
Environment::RunAndClearInterrupts / RequestInterruptFromV8
Isolate::InvokeApiInterruptCallbacks
[被中断的原调用栈]
EventEmitter<View>::Emit / View bounds layout
NativeWindowMac::SetContentView
BaseWindow::SetContentView → BaseWindow::BaseWindow
BrowserWindow::BrowserWindow → BrowserWindow::New
```

反汇编中 `this->isolate()` 载入 `x19`，随后访问 `[x19,#0x230]`；报告中 `x19=0`。系统报告原有的 TLSWrap / uv 标签来自 stripped binary 的近邻符号，不能据此判断 TLS 或定时器故障。

官方源码解释了该状态：`BaseWindow` 构造时先加入 observer 并 `SetContentView`，稍后 `InitWith` 才初始化 wrapper；`WillCloseWindow` 调用 `Emit` 时，后者在判断 wrapper 是否为空前使用 isolate 建立 HandleScope。inspector 能在布局事件期间中断构造并执行同步退出，从而进入尚未完成初始化的 observer。

源码依据：[BaseWindow](https://github.com/electron/electron/blob/v42.6.0/shell/browser/api/electron_api_base_window.cc)、[EventEmitter](https://github.com/electron/electron/blob/v42.6.0/shell/common/gin_helper/event_emitter.h)、[WindowList](https://github.com/electron/electron/blob/v42.6.0/shell/browser/window_list.cc)。符号来自 [Electron 42.6.0 官方发布](https://github.com/electron/electron/releases/tag/v42.6.0)。

## 可重复的因果验证

新增 `tests/e2e/startup-quit-reentrancy.spec.ts`，使用独立最小 Electron 入口，不加载产品、不加载页面或原生音频。通过 `bounds-changed` 回调把退出请求精确放在窗口构造中，对应历史栈的生命周期位置；仅临时替换事件入口，保留真实 Electron 窗口、原生关闭和进程退出。

该入口调用的就是产品启动 E2E 所复用的 `quitElectron` 回调，不是另造一份“修复版”。断言必须同时满足：构造期间确实请求退出、构造确实返回、触发 `will-quit`、进程自然 `code=0/signal=null`。

- RED：旧同步回调得到 `code=null/signal=SIGSEGV`；在加固后的隔离环境还原旧回调再次得到相同失败。
- GREEN：只将退出改为 `setImmediate(() => app.quit())`，上述断言通过。
- 该测试是确定性生命周期复现，不是原随机 inspector 调度概率的估计。
- 真实产品启动测试等待**首个窗口创建事件**后立即退出，不等待页面就绪、不打开编辑器；保留 `loading=true` 的实际启动状态。该测试与构造中请求测试覆盖不同边界。

## 可信隔离

复用现有 `-r` bootstrap guard，在产品主模块加载前安装：临时 userData/appData、阻止 legacy 迁移的 marker、Node HTTP/HTTPS、fetch、Electron net 和 child_process 共14入口的实际阻断验证，以及 Chromium 只放行本机5180 Vite的网络策略。

本轮补齐两个边界：子进程使用临时 cwd，避免模块加载阶段 dotenv 读取项目 `.env`；不继承父进程全部环境变量。HOME、TMPDIR、Electron home/documents/crashDumps/sessionData 都指临时目录并核验，路径重设不得越界。现有 SQLite/DOCX 测试仅通过临时目录中的 node_modules 链接解析仓库已安装依赖（Windows 使用 junction）。macOS `/var` 到 `/private/var` 的别名先 realpath，不能把路径别名误判为隔离逃逸。

本轮 Vite 用空 envDir 和最小环境在 localhost:5180 启动。未读取真实 legacy/用户数据库/凭据，未真实录音、推理、发送或写入系统剪贴板，未更改系统权限。诊断仅下载匹配的官方符号，不下载模型。所有成功退出断言在 fixture 清理前完成，清理的 app.exit/SIGKILL 不算成功证据。
