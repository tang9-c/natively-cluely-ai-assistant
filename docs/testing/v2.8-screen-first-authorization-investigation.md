# 首次屏幕录制授权路径调查

状态：首次权限分支修复已作为 `2.7.14` 提交、推送，但用户复测仍无授权弹窗／列表项。后续签名完整性修复已升级 `2.7.15` 并提交、推送；三平台构建通过，两个macOS平台最终ZIP／DMG内应用的严格签名校验通过。实机权限复测未完成，不正式发布。详见文末追加调查和2.7.15验收。

## 现象与证据

用户反馈候选包显示“屏幕录制权限被拒绝”，正文要求关闭再开启 CueUp，但截图中的“录屏与系统录音”和“仅系统录音”列表都没有 CueUp。截图只能证明当时界面中未列出应用，不能证明用户拒绝、TCC缓存过期或代码签名异常。

静态追踪发现：启动阶段有意不调用受保护 API，延迟到用户开始会议／截图时请求权限；但 `resolveMacScreenPermissionHealth` 遇到 `not-determined` 又提前返回 `effectiveGranted=false`、`recommendedFix=restart-app`，没有执行已有的 `desktopCapturer.getSources` 探测。会议随后跳过系统音频初始化。该分支构成可确定复现的首次授权路径缺陷；没有读取用户真实权限数据库，不能据此断言用户机器必然走过相同状态。

## 最小修复

- 去掉首次未决定状态的提前返回，用户主动使用采集时复用已有探测。有效可采集才放行；失败继续阻止系统音频，不假报授权成功。
- 启动和 `permissions:check` 的 `probeScreenSources=false` 分支保持被动；`restricted` 策略限制不探测，开发环境和非macOS行为不变。
- 将系统音频权限提示改为中文，标题不再把所有不可用状态断言为拒绝；系统音频和截图提示均补充列表中无 CueUp 时用“＋”添加的操作。同步移除“启动已经触发授权”的过时注释。
- 不新增 IPC，不自动重置权限、不重启应用，不改签名、音频后端或用户数据。

## 当前候选包的绕行与实机复测

完全退出 CueUp，在系统设置的“录屏与系统录音”列表下点击“＋”，选择安装在“应用程序”中的 CueUp，启用并重新打开。若从DMG或其他路径启动，应确认授权与运行的是同一安装副本。此步骤由用户操作，不自动执行权限修改。

修复版仍需远程构建后，在首次使用的测试系统用户上验证：只启动应用不弹授权；点击开始会议／截图可进入系统授权；同意后系统音频确实产生转录；拒绝时仅麦克风可继续且提示可操作；手动添加授权后重启复测。既有草稿 `v2.7.13-sha-94c63d0` 不含此修复，不能用旧包宣称修复通过。

## 用户复测未恢复：签名完整性追加调查

用户确认已在2.7.14中开始会议／截图，仍没有授权弹窗，系统列表中没有 CueUp。因此不能归结为“只启动但没有触发使用”。先前 resolver 模拟测试只能证明分支行为，不能证明 macOS 实际接纳授权请求；之前的 CI 架构与运行时检查也没有覆盖应用签名资源封印。

只读检查本机 `/Applications/CueUp.app`：Info.plist 版本为2.7.14，bundle ID为 `com.electron.meeting-notes`，ARM64、ad-hoc签名。`codesign --verify --deep --strict --verbose=4` 退出1，报告 `a sealed resource is missing or invalid`，具体为 `Contents/Resources/app.asar.unpacked/native-module/index.darwin-arm64.node` 被修改；单独校验该模块却通过。这是外层资源封印失效，不等于模块自身签名损坏，也不等于必须先购买签名证书才能调查。

根因已定位到 `scripts/ad-hoc-sign.js` 的顺序：先对整个应用执行 deep 签名，再重签 Resources 中的 `.node` 并写入 entitlements，却没有最后重封外层应用。修改内层文件后，外层封印仍保存旧哈希。此为可复现的打包缺陷，且与已安装包报出的具体文件吻合；尚无TCC现场轨迹能证明它是权限列表缺失的唯一原因，不把推断写成实机通过。

本地修复：保持现有深签及模块权限声明流程，模块完成后再签最外层应用（不加 `--deep`，避免再次覆盖内层权限），然后严格校验；模块签名失败不再吞错。两个macOS构建在最终打包应用检查中新增同样的严格校验，阻止无效包继续通过。Windows不新增macOS签名操作。

验证证据 `.tmp/screen-signature-investigation/`：

- 将已安装包克隆到任务临时目录：副本先严格校验退出1；仅重封外层后退出0；之后对完整副本运行修复后的hook，自然退出0并严格校验通过。原 `/Applications/CueUp.app` 未修改，也没有重置TCC或读取用户会议／凭据。
