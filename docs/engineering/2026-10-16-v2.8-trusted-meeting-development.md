# CueUp V2.8 详细开发方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 方案制定阶段仅写文档；2026-10-17 用户授权按 executing-plans 实施 T0/T1，执行状态见文末。未经用户或显式技能授权，不分派子代理。

**Goal:** 在原有会议流程内完成可信身份标注、音频自愈、摘要与转录直接编辑、专名纠正及时生效，以及统一纪要复制／Word 导出。

**Architecture:** 保留现有音频、识别、会后总结、SQLite、RAG 和 Electron IPC 主链路。先修稳定片段定位与增量保存，再接入编辑和分享；身份判定、行动项兼容整理、分享内容投影采用小型纯函数，禁止创建通用工作流或第二套数据系统。

**Tech Stack:** 仓库现有 TypeScript、React、Electron、better-sqlite3、sqlite-vec、docx、Node test、Playwright；不升级依赖，不增加编辑器、声纹或集成 SDK。

**Spec:** [V2.8 PRD](../product/V2_8_TRUSTED_MEETING_PRD.md)。产品范围以该文件已确认的 F1–F5 为准。

## 3. 数据、接口及兼容约定

### 3.1 稳定片段与迁移

现有数据库有 `transcripts.id`，但详情没有返回该 ID；内存片段有 marker/rawSegmentIds，写库未完整保留。身份覆盖键还依赖文字前缀，因此不能把当前文字作为编辑定位键。

采用一个持久化 `segmentId`：新最终片段在主进程分配 UUID，临时片段不可持久编辑；旧记录回填 `legacy:<meetingId>:<transcripts.id>`。合并时保留首片段 ID，原片段别名沿用现有 alias 机制；已被用户编辑／纠正的片段不再与后续段落合并。最终负载、会话、数据库详情、虚拟行共享同一 ID 及别名体系：实时 IPC 仍按原始 final 粒度发送，数据库保存首 canonical ID 与全部原 ID 别名；后续 F1 界面需明确合并片段的纠正范围。去重分支同样必须将 incoming ID 及旧定位键映射至保留片段。

基线迁移版本为 37，本分支新增 v38（若执行时已占用，使用紧接的版本，不复用既有版本号），事务内增加：

- `transcripts.segment_id`：TEXT，回填后建立 `(meeting_id, segment_id)` 唯一索引。
- `transcripts.original_content`：TEXT，仅第一次手工文字编辑时保存原文；不是历史版本系统。
- `transcripts.raw_segment_ids_json`：TEXT，实施审查确认的必要补充，保存合并／去重的原始 ID 别名，供重载后稳定定位。
- `transcripts.edit_revision`：INTEGER，默认 0，文本和身份编辑共享该片段版本。
- `meetings.edit_state_json`：TEXT，默认 `{}`；保存 meetingRevision、transcriptRevision、summarySourceRevision、editedSummaryFields、indexDirty。缺字段按 0／空集合／false 读取。

不更改 speaker 列的音源路由含义。`speaker_identity_correction_json` 兼容旧 `isMe`，新增加显式 `identity: me|other|unknown`，恢复自动判断才删除该对象。保留原始声纹证据，不把人工确认伪装成 confidence=1 的模型判断。

只增加列，不重建会议表、不批量改写摘要。新写法停止使用整份 `INSERT OR REPLACE` 覆盖已有会议。执行迁移前在测试数据库副本验证行数、外键和原文不变；正式升级沿用数据库备份流程，没有现成可靠备份则先补备份再启用迁移。

### 3.2 编辑与生成写入

- `applyMeetingEdit(request)`：新增 DB 方法。请求包含 meetingId、expectedRevision，以及一种操作：summary patch、单段 text、同一会议的 identity 批量操作。更新事务只写指定字段，校验 ID 属于该会议。
- summary patch 白名单：title、overview、keyPoints、decisions、openQuestions、sections、actionItemsTitle、keyPointsTitle、actionItemsStructured；禁止任意 JSON merge，禁止客户端写生成状态和 edit_state。
- 结果为成功（新 revision、更新后 Meeting）或失败（not_found、conflict、invalid_input、save_failed）。批量身份操作全部成功或全部回滚；未知段 ID 不允许部分成功。
- 新 IPC `meeting-apply-edit`、preload `applyMeetingEdit`、renderer 类型同步。现有 `update-meeting-title/summary` 保留兼容，但内部走同一事务规则，标记人工修改，不能继续绕开保护。
- live 身份纠正扩展既有 `speaker-verification:set-session-override`，新增 segmentId 和 sessionGeneration；旧参数仅兼容已有调用，更新 UI 后不再用文字定位。stop 后晚到事件不允许改到下一场会议。
- 生成完成使用 `mergeGeneratedMeetingResult`，只补未被人工编辑的摘要字段和标题，保留已有转录、身份、usage 和删除结果。会议已删除时不得重新创建。
- 初次总结发起前读取最新已保存转录并记录 transcriptRevision；在模型处理中发生修正时，允许保存本次生成，但标记依据过期，不自动二次调用。编辑动作永远不被旧生成结果覆盖。

客户端每个会议使用一条串行保存队列，不为每个字段创建竞态请求。收到 conflict 后读取最新状态：目标字段未被别人改动可基于新 revision 重试一次；目标字段已变化则保留本地草稿、提示重新加载或保留本次修改，不静默覆盖。保存失败时不允许复制／导出旧版本冒充当前版本。

### 3.3 三类身份，不改变音源

在 `shared/speakerIdentity.ts` 增加 `resolveSpeakerIdentity(segment)`，返回 identity（me/other/unknown/numbered）、label、source（manual/voice/provider/unknown）；既有 `resolveEffectiveSpeaker` 只作兼容适配，不再供 UI 把 user 默认翻译成“我”。

优先级：人工选择（包括 unknown）→ 有效本人声纹 → 带提供商证据的说话人编号 → unknown。缺少证据、负匹配和近阈值结果不确定为他人。声纹字段须校验有限数值、provider/profileId、isMe=true 且达到阈值；明确合并多个音频单元或存在多人风险的片段不使用整段阳性证据认定本人。

### 3.4 行动项唯一来源

继续使用现有 `actionItemsStructured`，不新增第三套任务表；在明确升级到 summary schemaVersion=3 后，即使该数组为空也视为权威，防止已删除任务从旧字符串列表复活。`actionItems` 仅作为由统一清单派生的兼容字段，所有生成、编辑、显示、检索、导出均经同一规范化入口。

旧数据合并规则：以已有字符串行动项的顺序和文字为先；规范化空白、末尾标点后完全相同的任务，且负责人／期限不冲突时合并，补齐空元数据。无匹配的结构化任务追加。文字相近但不相同不作语义去重；同文但元数据冲突保留两条原记录供直接修改，不随意选择负责人。用户不看到第二个“下一步”区块。保留已有 ID，新增项分配稳定 ID，来源时间只存储不宣称为引用。

### 3.5 分享与完整档案

新增 `copy-meeting-minutes` IPC：按 meetingId 和 expectedRevision 读取当前落库内容，在主进程执行剪贴板 text+html 写入，返回成功／冲突／失败。不能接收 renderer 提供的任意 HTML。取消 markdown 展示符号通过既有解析库转换，HTML 仅输出转义后的安全标题、段落、列表，不嵌入图片、脚本或远程资源。

扩展现有 `export-meeting-docx` 参数 profile=`minutes|archive`：旧 includeTranscript=false 对应 minutes，true 对应 archive；保留既有签名适配。minutes 读取同一分享投影，archive 保留原完整档案能力及明确包含转录的入口，不进入简洁分享菜单。

分享投影只取 title/date、overview、keyPoints、decisions、统一行动项；不遍历整个 summary 对象，不拼接 usage/coachingInsights/followUpDraft/transcript。模式 sections 只纳入现有明确的会议事实类别（概要、要点、决策、行动），已归入其他区块的内容不重复，私人辅导类别一律排除。Markdown overview 中明确独立标记的辅导／私人问答／跟进草稿章节也剔除；不声称可自动识别任意混入普通段落的私人内容，不新增 AI 隐私分类器。特殊旧模板在夹具中明确覆盖。

## 6. 验收矩阵与发布门槛

### 6.1 自动化硬门槛

| 范围 | 必须满足 |
|---|---|
| 数据兼容 | 旧库迁移不丢会议／转录／身份；幂等；失败回滚；summary 回写不改变 transcript 行标识 |
| 身份 | 规则表全覆盖；无证据 mic 不标本人；人工 unknown 不被覆盖；带编号的云端片段不因声纹失败丢编号 |
| 自愈 | 假时钟下安静不误恢复；每路最多一个恢复任务；恢复成功需证据；stop 后零残留任务 |
| 编辑 | 生成、保存、索引并发不丢修改；保存失败不输出旧版本；已删除任务不复活 |
| 专名 | 不重启即时生效；整句不入词表；重复幂等、冲突不覆盖；手工编辑所有来源可用 |
| 分享 | 两个出口；内容一致；排除私人字段；XSS 输入仅作为文字；取消保存正常 |
| 性能 | 5,000 段虚拟列表 DOM 行数继续 <40；滚动卸载不丢草稿；无整篇按键级重索引；验证等待不超过既有 200ms 预算及调度容差 |

### 6.2 真实环境验收（获准后执行）

- 平台：macOS Apple Silicon、macOS Intel、Windows x64；两种本地识别至少各有一套可运行模型。缺任何平台则相应项未通过，不以“编译成功”代替。
- 会议：线下多人、线上双通道、混合会议各至少 2 场，每场至少 20 分钟；线下／混合至少 3 名发言者，包含远场、短句、停顿和插话。若使用事先获准录音回放，明确不能替代硬件现场验收。
- 身份：冻结至少 100 段本人清晰单人语音、100 段非本人清晰语音，以及单独的噪声／重叠集合。拟定工程准入门槛：非本人误标本人率 ≤1%，清晰本人正确识别率 ≥80%；噪声／重叠优先未知，单独报告，不通过过滤未知提高分数。此为目标，不是现有模型能力结论；不达标不降低阈值冒充通过，先修复／校准，仍不达标则阻止声纹自动标注的发布确认。
- 音频：每个平台执行设备拔插、输出路由变化、休眠恢复、权限撤销／恢复、正常静音，每种至少 3 次；应保留已采集文字，恢复失败有操作入口。各后端报告检测和恢复耗时，不宣称补回中断内容。
