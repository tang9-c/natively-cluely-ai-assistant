# 统一性能基线 PRD

## 状态

- 状态：已完成
- 目标平台：Apple M4 / 16GB
- 命令：`npm run perf:baseline:all`
- 当前行为：完整模式复用通过 schema、机器、样本数、采样器哈希、独立复算和隐私检查的已有报告，只补采缺失或失效场景。统一报告会明确记录 `reused`、`collected`、`resumed` 或 `excluded`，复用不冒充本次新实测。

## 产品目标

提供一个统一入口，自动完成性能基线的环境检查、样本采集、断点续跑、报告聚合和验收，避免后续开发人员手工组合多个零散脚本。

底层采样器继续独立运行。统一入口只负责编排，不将所有场景合并成一个不可定位失败原因的单体测试。

## 使用方式

完整采集与验收：

```bash
npm run perf:baseline:all
```

快速检查，不执行 30/60 分钟长会议和高样本量真实调用：

```bash
npm run perf:baseline:all -- --quick
```

从已有脱敏样本和 sidecar 状态继续补跑：

```bash
npm run perf:baseline:all -- --resume
```

只执行指定场景：

```bash
npm run perf:baseline:all -- --only qcloud-stt,rag
```

## 覆盖范围

统一入口必须编排以下指标：

1. 应用冷启动时间。
2. 音频输入到最终转录结果的延迟。
3. 转录结果到动态动作卡片的延迟。
4. LLM 首 token 延迟和完整响应时间。
5. RAG 查询耗时。
6. 会议结束到摘要完成时间。
7. 30 分钟和 60 分钟会议的 CPU、内存及数据库大小。
8. Renderer 长时间运行后的卡顿和重渲染次数。
9. QCloud STT 分段提交到 renderer 的阶段延迟。

## 执行要求

统一入口必须：

- 检查当前机器是否为 Apple M4 / 16GB。
- 只检查凭据是否存在，不输出凭据值。
- 构建 Electron，并复用或启动一个 Vite 服务。
- 严格串行执行真实 QCloud 采样，禁止并发增加费用和限流风险。
- 每个场景完成后原子保存脱敏样本，支持 `--resume` 只补缺失样本。
- 保留每个底层测试的独立状态、失败阶段码和报告路径。
- 对所有有效样本生成 p50/p95，不使用平均值替代。
- 独立复算样本数、p50/p95 和验收状态。
- 执行隐私扫描，不允许报告包含凭据、原始音频、原始转录、请求体、响应体或异常正文。

## 输出

完整模式提供两份正式报告：

```text
reports/performance/m4-16gb/unified-final.json
reports/performance/m4-16gb/unified-final.md
```

底层场景报告继续保存在各自目录，用于定位失败，但不得要求用户手工合并。

快速模式输出 `unified-quick.json/.md`，指定场景模式输出 `unified-selected.json/.md`。两者与正式报告隔离，不能替代完整基线验收。

## 退出状态

- 退出码 `0`：所有必需场景有有效样本、p50/p95，且不存在 `blocked` 或验收失败。
- 非零退出码：任一必需场景缺样、失败、质量不合格、报告复算不一致或隐私扫描失败。
- `--quick` 的成功只代表快速检查通过，不得替代完整性能基线验收。

## 完工标志

以下完工条件均已满足：

1. `package.json` 存在 `perf:baseline:all` 命令。
2. 完整、`--quick`、`--resume` 和 `--only` 均有自动化测试。
3. 真实运行能够调用现有独立采样器并生成统一 JSON/Markdown 报告。
4. 中断后重新执行 `--resume` 不会重复已有有效样本。
5. 任一必需指标为 `blocked` 时命令返回非零退出码。
6. Apple M4 / 16GB 目标机完整运行后，统一报告中所有必需指标都有有效样本和 p50/p95。
7. 独立复算、隐私扫描和相关测试全部通过。
