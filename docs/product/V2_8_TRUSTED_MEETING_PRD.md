## 1. 背景与目标

用户反馈：本地模型用于线下多人会议时，所有发言被标为“我”，削弱会议记录可信度。错误身份还可能影响摘要、任务归属和发言分析。

V2.8 的目标流程：直接开始会议，后台保障收音 → 如实记录 → 原地纠错 → 复制纪要或导出 Word。无需额外会前检查向导或逐项审核流程。

优先覆盖线下共用麦克风、线上双通道、会议室设备负责线上音频而个人电脑独立收音的混合会议。本地模型是重点验收路径；云端遵循相同身份和展示规则。

## 3. 共同原则与版本边界

- 音源、说话人编号、真实身份分别表达；系统音频也可能包含多个人。
- 不确定性贯穿转录、摘要、行动项和导出；未知身份不能被自动变成确定负责人。
- 人工修改应持久保存，不被后续生成静默覆盖；依据变化后提示结果可能过期。
- 分享使用最新成功保存的内容；复制或导出失败不影响会议记录。接收对象及最终发送由用户在飞书等目标应用中处理，CueUp 不新增发送预览或确认流程。
- 凭据保护与可靠保存是发布前提，不占五项功能名额。
- 暂不包含手机镜像、日历同步、更多模式或模型、终端任务代理、第三方账号或机器人接入、系统分享菜单、云端分享链接、外部任务同步或自动发送。

## 4. F1：可信的本人识别与片段身份纠正（已确认）

### 4.1 目标与非目标

停止凭麦克风来源将所有发言标为本人。有依据才标本人，标错可以直接纠正，纠正结果贯穿记录和交付。

首版优先复用现有声纹注册、本人验证、云端编号及片段纠正。暂不引入完整本地多人自动分割、多人姓名库、声纹自动学习或姓名传播；自动区分其他参会者为 A/B/C 是后续独立验证项。

### 4.2 当前实现依据与限制

- `electron/main.ts` 将麦克风识别通道设为 `user`，系统音频设为 `interviewer`，角色沿用到转录负载。
- `shared/speakerIdentity.ts` 当前只解析人工二选一纠正；`src/components/meeting/TranscriptRow.tsx` 将有效角色转换为“我／对方”。
- 已有本地声纹模型、本人档案、注册与健康检查；档案仅支持 `me`。
- SenseVoice 已调用声纹标注器；此次核查未发现 LocalWhisper 调用该标注器，需补齐实际调用。
- 当前 `isMe=false` 表示相似度低于本人阈值，不足以确定“不是本人”；音质、距离和短句均可能影响结果。
- 豆包 AUC、腾讯云相关路径已有提供商说话人编号解析；编号不代表真实姓名。
- 人工纠正主要从动态动作卡片进入，不是完整的会后转录编辑功能。

以上是静态代码核查，不能替代真实多人录音验收。

### 4.3 统一身份规则

按以下优先级解析，音源不构成人物身份证据：

| 依据 | 展示 | 约束 |
|---|---|---|
| 用户明确标记本人 | 我 · 已确认 | 优先于自动识别 |
| 用户明确标记非本人 | 其他参会者 · 已确认非本人 | 不意味着多个片段来自同一个人 |
| 用户明确标记未知 | 身份未确认 | 保留人工选择，直到用户恢复自动判断 |
| 声纹有效匹配 | 我 · 声纹匹配 | 展示自动判断来源，允许纠正 |
| 提供商有效说话人编号 | 说话人 1／2… | 保留现有能力，不推断真实姓名 |
| 无人工确认、无有效声纹匹配且无有效提供商编号 | 身份未确认 | 未注册、验证失败或低于阈值不证明是他人；仍有有效提供商编号时沿用上一行 |

会中临时转录未完成验证时先显示身份未确认；最终结果到达后更新。声纹相似度不显示成经过校准的身份正确率。

### 4.4 本地识别与生命周期

- SenseVoice 复用已有验证结果；LocalWhisper 补齐最终转录对应音频的验证调用。
- 开启、暂停或重新注册后，下一段符合条件的音频采用最新状态，无需重启应用。
- 验证仅使用对应片段音频；拼接多个潜在说话轮次的片段，不凭一次匹配将整段确认为本人。
- 模型缺失、超时、音质不足时转录继续，身份降级为未确认；不让身份验证无限等待或阻断转录。
- 复用现有模型和注册界面，不额外上传音频，不新增永久原始音频存储。

### 4.5 人工纠正

会中转录和会后记录的身份标签提供：标记为我、标记为其他参会者、标记为身份未确认、恢复自动判断。

默认只修改当前片段；会后支持选择多个片段批量修改。禁止以音源为依据执行“全部麦克风片段改为我”，禁止把全部未知片段当作同一个人批量命名。

纠正持久保存，重新打开会议仍生效；不自动更新长期声纹档案。现有动态动作卡片复用同一纠正规则。

片段定位优先复用原始片段 ID，旧记录保留兼容定位，避免文字编辑使身份纠正失效。人工确认保留独立来源，不伪装成模型置信度。

### 4.6 下游一致性与 F3 边界

- 会中、会后、复制、导出采用统一身份依据，未知身份不再输出为“我”。
- 摘要、行动项和跟进草稿不根据麦克风通道把承诺归给用户。
- 未知发言者说“我下周提供资料”时，负责人待确认；原话明确提到“张三负责”时可按内容提取，并保留依据。
- 动态动作涉及本人／他人差异时沿用确认机制；统计与评价不将未知片段直接计入本人。
- 身份修改后提示已有摘要可能需要更新，不静默覆盖人工编辑。按后续确认的 F3 收敛范围，首版通过直接编辑修正摘要，不新增重新生成流程。

### 4.7 历史记录与兼容

保留原始通道、文字和已有人工纠正。旧记录仅有通道且无可靠身份依据时显示身份未确认，并在会议级说明旧版本曾按音源标注。

不自动改写历史摘要；用户在 F3 直接编辑修正，不新增历史摘要重新生成。内部通道字段继续服务音频路由，身份单独解析，避免改变旧角色语义导致音频行为回归。

### 4.8 验收

| 场景 | 预期 |
|---|---|
| 未注册声纹，三人共用麦克风 | 不因麦克风来源标为本人 |
| 已注册，本人与他人轮流发言 | 有效匹配可标本人，其余保留未确认 |
| 远场、短句、噪声 | 匹配失败不直接判为他人 |
| 插话或片段包含多人 | 不无依据地确认整段为本人 |
| 会中开启、暂停、重录 | 后续片段采用最新状态 |
| 人工纠正后重新打开 | 纠正保留，复制与导出一致 |
| 未知身份表达承诺 | 不自动把任务分配给用户 |
| 声纹模型不可用 | 转录继续，身份降级明确 |
| 人工标为未知后自动结果到达 | 不覆盖人工选择 |

真实样本分别统计他人误标为本人、本人正确识别、未确认比例及额外延迟。样本、基线和数值门槛需在工程验收方案中确定，不以减少未知比例换取更多误归属。本地回归与真实音频验收分别记录。

## 5. F2：完善现有音频自愈体验（已确认）

### 5.1 产品目标与范围

用户仍直接使用原有“开始会议”。后台先尝试恢复，确实需要用户处理时才出现操作入口。正常时不打扰、异常时说清楚、恢复后状态正确。

不新增收音检查页面、场景选择向导、双通道仪表盘或独立修复系统，不要求用户理解采样率、缓冲区或 STT。设备选择和麦克风测试保留在现有设置中。

### 5.2 复用能力

- `electron/main.ts` 已有采集错误后的重建、麦克风不可用时默认设备回退、默认输出变化跟随及休眠恢复。
- 已有启动无数据、全零音频检测和识别服务状态事件。
- `src/components/NativelyInterface.tsx` 已有异常提示和 macOS“修复权限并重启”入口；后者用于清理异常权限缓存并重新触发系统授权，不能代替用户授予权限。

以上为代码存在性核查，不代表所有设备与故障均已通过真实验证。

### 5.3 三项补强

1. **该修复时能够触发。** 验证并补齐会中停止供音但未抛错等遗漏路径。区分正常安静与异常断流，依据各后端的数据输出行为判断，不统一套用“无声即故障”。
2. **恢复成功有真实依据。** 收到恢复后的有效采集证据再更新状态；创建对象或调用启动成功不等于采集恢复，采集恢复也不等于转录已经完成。各重建路径接回相同的必要监测，设备回退后显示实际设备。
3. **修不好才打扰用户。** 复用现有提示、设置与权限修复入口，一句话说明受影响的能力和主要操作；自动恢复采用已有策略，避免重复重试机制和重复弹窗。无法自动处理的权限问题直接提供对应操作，不进行无效重试。

短暂恢复期间尽量安静，持续故障不能无限隐藏。单路故障不停止仍正常工作的音源；必要音源失败不能因为另一音源正常而被掩盖。正常安静不弹故障提示。

会中查看状态不得另外打开测试采集实例。权限重置或应用重启继续由用户主动触发，不在自动恢复中静默执行。

### 5.4 验收与非目标

- 设备断开、会中断流、权限异常、默认输出切换和休眠恢复分别验证。
- 正常安静不误报；修复中的状态不假报成功，恢复后状态与实际输入一致。
- 回退设备可见；单路失败不影响正常通道，也不会掩盖缺失。
- 修复失败有明确可操作提示；重复故障不反复打扰，已有转录不丢失。
- 不承诺补回未采集音频，不新增回声消除、重复音频去重或“所有参会者必然听清”能力。

此前提出的会前检查向导、会中仪表盘及会后异常时间线不属于本次已确认范围；现有完整性提示可保留，但不因此扩展独立功能。

## 6. F3：合并行动项、支持直接编辑（已确认）

### 6.1 产品目标

用户在哪里发现摘要错误，就在哪里修改。保留现有会议详情页和自动保存方式，不新增会议编辑器、任务管理页或审核流程。

### 6.2 统一行动项

- 将当前“行动项”和“下一步”合并为唯一的用户可见“行动项”清单，保留有效的内容、负责人和期限。
- 兼容历史记录，不直接丢弃任何一份独有任务；存在冲突时不凭空选择负责人或期限，不用简单删除另一份实现合并。
- 内容、负责人、期限可直接修改；缺少明确依据时显示待确认，遵循 F1 身份规则。
- 编辑、删除、重新打开和 F5 分享使用同一份有效结果，不继续维护两套独立编辑状态。F3 负责统一数据与保存，F5 负责对外内容选择、排版与输出。

### 6.3 直接编辑与保存

- 复用现有 `EditableTextBlock`、会议摘要更新 IPC 和数据库保存链路，补齐摘要正文和展示的结论条目等必要编辑入口；结构化行动项使用同一持久化来源。
- 用户直接点击内容编辑，自动保存；不新增必须逐项确认或手动提交的操作。
- 保存成功才显示已保存；保存失败保留输入并提供重试，不能将仅在界面修改视为持久保存成功。
- 摘要修改不反向改写转录，也不自动加入专名词表。
- 人工修改不能被异步生成结果静默覆盖；复制、导出前应使用已成功保存的最新结果，保存失败时明确提示。

### 6.4 与 F4 的边界和非目标

转录正文纠错、记住专名及词表生效归 F4；F3 仅处理摘要与行动项的直接编辑。

本次确认范围不包含原先建议的“查看原话”跳转、自动引用补齐、重新生成摘要、版本管理或差异对比。转录或身份变化后，可轻量提示摘要可能需要修改，由用户在现有页面直接编辑；不得出现尚未实现的“更新摘要”按钮承诺。

### 6.5 验收

- 同一会议不再出现两份互相矛盾、独立编辑的任务清单。
- 合并保留旧记录的有效任务、负责人及期限，未知信息不被自动补全。
- 修改一次，重开、复制与导出均一致。
- 保存失败可重试，输入不丢失；异步结果不覆盖人工修改。
- 修改摘要不会改变原始转录或长期词表。

## 7. F4：转录直接纠错与按需记住专名（已确认）

### 7.1 产品目标与已有基础

用户在现有转录页直接改字、自动保存；遇到反复出现的专名错词，再主动选择记住。不给普通文字修改增加弹窗或必经操作。

复用 SenseVoice 的内置及用户词表、正确词／错词映射、启用与删除、设置管理页及识别后替换逻辑。该能力是文本纠正，不是模型训练或热词识别概率提升。

当前转录缺少完整编辑保存链路；SenseVoice 实例在构造时保存词表配置，需修复设置保存后旧实例仍用旧规则的问题。

### 7.2 点击转录直接修改

- 在现有转录页编辑已经完成的片段，自动保存，保留时间、身份和稳定片段关联，不修改其他片段。
- 手动编辑适用于所有识别来源；保存失败保留输入并提示重试。
- 重新打开、复制与导出使用修正文字；历史检索同步更新，避免持续引用旧错词。后台处理不增加用户操作，并遵守原有数据作用域和提供商配置；索引更新失败可重试，不能假报已同步。
- 复用 F1 稳定片段标识，避免改字使人工身份纠正丢失。
- 首版不增加全篇替换、批量审校或独立编辑页面。

### 7.3 按需记住专名

用户选中具体错词并修正后，可主动选择“记住：错词 → 正确词”，确认后保存到现有词表。不默认勾选，不每次编辑都弹窗。

整句修改只保存文字，不自动推断长期规则；未明确具体词对时，不自动写入词表。重复规则复用，同一错词已有不同目标时提示冲突，不静默覆盖。沿用现有规则校验，无法保存时说明原因，不悄悄截断或忽略后宣称成功。

查看、停用和删除仍在现有词表管理页完成；不另建个人记忆管理系统。

### 7.4 生效范围

- 新增、停用和修改后，下一段 SenseVoice 最终识别结果采用最新规则，无需重启。
- 首版自动应用仍限定 SenseVoice，界面明确标注；其他模型可手动编辑，不宣称已支持自动词表纠正。
- 保存长期规则不自动批量改写历史会议，也不修改当前会议的其他已有片段。
- 只保存正确专名不意味着提高识别率，需要具体错词映射。

### 7.5 与摘要的关系

转录修改不静默改写已有摘要，轻量提示“转录已修改，摘要可能需要调整”。用户按 F3 直接编辑摘要，不新增重新生成流程，不覆盖人工修改。

### 7.6 验收

- 编辑后重开、复制、导出一致；时间和人工身份纠正保留。
- 保存失败输入不丢失；检索更新失败不回退已保存文字，后续能够重试。
- 普通句子修改不自动生成词表规则；明确词对经用户主动选择才记住。
- 重复规则不重复新增，冲突不静默覆盖；不合规规则不假报成功。
- 新规则及停用操作对运行中的 SenseVoice 后续最终结果生效，不依赖重启。
- 不回写其他历史片段、不自动修改摘要；其他识别来源不误宣称支持自动纠正。

## 8. F5：分享纪要（已确认）

### 8.1 产品目标与入口

在现有会议详情页提供“分享纪要”入口，只有两个操作：**复制纪要**（主要操作）和 **导出 Word**（次要操作）。复用现有剪贴板和 Word 导出能力；会议列表已有导出入口使用相同内容规则，不另建一份导出逻辑。

复制后用户到飞书等应用自行粘贴发送；Word 导出后用户自行选择接收方发送文件。不连接账号，不配置机器人，不读取群列表，不代替用户发送。

### 8.2 内容与排版

- 默认包含会议标题、日期、摘要、决策和 F3 统一的行动项；负责人和期限采用已保存值，未知信息不补全。
- 使用最新成功保存的修改，不再次调用 AI 生成分享版本。未完成保存时先完成保存，失败则保留输入并提示重试，不输出过期版本。
- 默认排除私人问答、辅导评价、完整转录和跟进草稿。现有独立的转录复制、包含转录的导出、草稿复制入口保留，不混入简洁的“分享纪要”菜单。
- 摘要字段中含有模式内容时也要按上述规则整理，不因为字段名叫“摘要”就将独立私人分析拼入。
- 复制与 Word 采用同一份内容快照，仅版式不同；段落、标题与列表清晰，不输出无内容的占位章节或多余 Markdown 标记。
- 剪贴板优先同时提供富文本和纯文本；在飞书 macOS、Windows 客户端验证实际粘贴效果，不承诺所有应用都保留相同格式。

### 8.3 反馈与边界

- 剪贴板写入成功才提示“已复制”；失败显示“复制失败，请重试”。不提示已发送，不自动打开聊天或选接收人。
- Word 沿用系统保存对话框；保存成功才显示已导出，用户取消不报错。
- 不增加独立预览、分享审核页、云端托管链接、系统分享面板、飞书或 Slack 集成、多平台配置与外部任务同步。
- 两端采用相同操作，不依赖飞书注册系统分享扩展。系统分享是否支持飞书不再作为 V2.8 的交付条件。

### 8.4 验收

- 菜单只有复制纪要和导出 Word；无需登录或平台配置。
- 两种输出包含相同的最新已保存信息，行动项只有一份；不默认包含上述排除内容。
- 自动保存期间触发分享、保存失败及快速连续编辑时，不输出旧版本或丢失修改。
- 复制成功反馈准确，Word 取消与失败正确区分。
- 在 macOS、Windows 验证中文、英文专名、长段落、列表和负责人／期限；飞书粘贴结果可读，Word 可正常打开且内容完整。

## 9. 五项功能协作与范围检查

| 功能 | 负责 | 不负责 |
|---|---|---|
| F1 | 片段身份判断、人工身份纠正及下游身份规则 | 本地多人聚类、姓名库、文字纠错 |
| F2 | 复用音频自愈，补触发、恢复验证和必要提示 | 新检查向导、仪表盘、身份识别 |
| F3 | 摘要原地编辑、唯一行动项清单及保存 | 转录编辑、词表、重新生成、引用跳转 |
| F4 | 已完成转录片段编辑、明确词对记忆与 SenseVoice 热更新 | 摘要改写、全篇替换、跨模型自动词表应用 |
| F5 | 将已保存结果整理成纪要并复制／导出 | 内容重新生成、平台连接、最终发送 |

共同约束：

- F1 与 F4 共享稳定片段关联，改字不能丢失身份纠正，改身份不能覆盖文字。
- F1/F4 的修改不回写已有摘要。摘要已生成时，两类修改复用一条会议级轻量提示，不为每个片段弹窗；摘要尚未生成时不提示过期，后续生成使用有效记录。
- 已有摘要初次生成与自动保存并发时，保留人工修改。F3 不新增重新生成按钮，F4 不通过后台重算绕过此边界。
- F1 的会后批量身份纠正已确认保留；F4 不支持批量文字替换，两者不矛盾。批量身份操作按需出现，不占默认界面。
- F2 的采集恢复只报告音频状态，不宣称转录完整或身份准确。
- F3 统一内容保存，F5 只读取与格式化。转录独立导出遵循 F1/F4，纪要默认不包含转录。
- 新增功能不改变已经保存的会议内容，除非用户明确编辑；旧记录的展示与行动项兼容整理不得丢失信息。

工程阶段需细化但不得扩展产品范围的事项：历史行动项冲突合并规则、编辑并发与稳定 ID、索引刷新及失败恢复、各音频后端故障阈值，以及真实声纹验收样本和数值门槛。这些不等于已完成实现或实机验证。

## 10. 版本级验收

以获准使用的真实会议样本覆盖线下、线上和混合场景，并分别检查本地与云端路径。验证“开始会议 → 自动恢复异常 → 修改身份与文字 → 编辑摘要及行动项 → 复制纪要／导出 Word”的完整流程和内容一致性，以及用户将会议结果整理到可交付状态所需的时间。

真实外部验收单独记录，不以本地测试替代；未经授权不调用外部服务、采集真实会议或发送内容。暂不承诺发布日期。
