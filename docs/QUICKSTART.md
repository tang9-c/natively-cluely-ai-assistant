# CueUp 快速入门

本指南帮助你在第一次打开 CueUp 后完成必要设置，并开始记录一次会议。

适用版本：2.7.22，核对日期：2026-10-31。[功能与设置参考](REFERENCE.md)说明检查状态与限制；[会议辅助指南](HOWTO_MEETING_ASSISTANCE.md)说明日常操作。

## 1. 第一次启动

首次安装并打开 CueUp 后，点击欢迎页的“开始设置”，按“设置概览 → 权限与设备 → 语音识别 → AI 提供商 → 开始会议”完成初始设置。也可稍后从“设置 → 通用 → 初始设置”继续；高级选项保留在设置页。建议依次：

1. 授予麦克风权限。
2. 选择并准备语音转写模型。
3. 保存并验证 AI 配置，确认“允许 AI 使用转写内容”的选择。
4. 核对设备与保留策略，再点击“开始会议”；需要屏幕辅助时，另行检查相应系统权限。

macOS 用户在“系统设置 → 隐私与安全性 → 麦克风”中允许 CueUp 使用麦克风。Windows 用户检查系统的麦克风隐私与桌面应用访问设置；不要以是否出现一次性授权弹窗判断能否采音。

在“权限与设备”中选好输入和输出，点击“检查电平”可测试麦克风输入，不录制或转写。点击“刷新设备与权限”后应看到刷新中、完成或读取失败的反馈。系统音频显示“使用时确认”或“尚未确认系统音频授权”时，可以继续配置；实际采集在开始会议时检查，屏幕录制开关不能单独证明系统音频可用或受限。

点击“稍后继续”后，可从首页“继续设置”或通用设置返回。已有配置会沿用，旧用户不会被当成全新安装而强制重配。离开有修改的页面时，选择保存、放弃或留在原页。

## 2. 选择语音转写方式

在初始设置的“语音识别”页，或“设置 → 音频 → 语音提供商”选择一种转写方式：

- **本地 SenseVoice（推荐）**：模型下载完成后可在本机转写，适合优先保护本地会议内容的场景。
- **QCLOUD API 或豆包 AUC**：需要先配置对应服务；可提供云端语音转写，并支持说话人分离。
- **本地 Whisper**：仅用于兼容已有使用方式，不是新的默认推荐方案。

本地 SenseVoice 不提供通用的多人说话人分离。若会议记录需要区分多人发言，请选择已配置的 QCLOUD API 或豆包 AUC 语音服务。

选择与你的会议匹配的“会议语言”。QCLOUD API 当前支持这里的“中文”与“自动”中文优先策略；本地 SenseVoice 支持中文、英文、日语和韩语。语言选项列表不代表每个服务都支持所有选项；以当前兼容性检查为准。切换语言、服务或模型后，保存并重新检查。

本地模型点击“下载模型”，完成下载和加载检查后再继续；下载期间可先配置 AI。云端点击“保存并验证语音服务”。这些检查不采集你的声音，云端验证可能发送内置样本；凭据访问成功不代表真实会议已经成功转写。

## 3. 配置 AI 回答服务

CueUp 未配置时的聊天默认模型为 Doubao Seed 2.0 Lite，调用前仍须配置服务。QCLOUD API Key 在“设置 → QCLOUD API”中管理，语音识别与 AI 共用同一份 Key，切换服务后可复用，无需另申请语音密钥；服务端仍须提供相应权限。使用 QCLOUD 时，账号和令牌在初始设置提供的 QCLOUD API 平台入口管理，不使用火山引擎的开户指引。豆包语音 Key 与豆包 AI Key 分别配置。其他提供商、自定义端点及聊天默认模型在“设置 → AI 提供商”中管理。

初始设置可直接验证 QCLOUD API、豆包和 Codex CLI。Codex 的“检测 CLI”只证明找到程序，仍需验证实际请求；其他历史/自定义配置保留，在原设置中维护。点击“保存并验证”后，以“本次模型响应通过”为本次结果；“上次验证通过”带历史时间，不代表本次重新请求。仅显示“密钥已保存”时，还未证明连接成功。

如使用云端服务，请在“设置 → AI 提供商 → AI 数据范围”检查数据范围授权。这是全局范围策略。初始设置中的“允许 AI 使用转写内容”与该页共用同一设置，关闭后无法完成首次 AI 设置，可稍后继续。该开关不关闭云端语音识别的原始音频上传；要避免音频为转写外发，应选择本地语音识别。没有可用且允许的替代服务时，相关 AI 功能会提示限制。

## 4. 选择会议模式

模式为 CueUp 指定当前会议的助手角色、实时提示方向和会后笔记结构。打开模式管理器，选择模式并点击“设为活跃”；需要恢复默认时点击“停用”，即可回到“通用”模式。

CueUp 提供 8 种内置模式：

| 模式 | 适用场景 | CueUp 重点帮助你记录或处理什么 |
| --- | --- | --- |
| **通用** | 没有明确专项目标的普通会议、沟通或问答 | 摘要、要点与行动项。 |
| **销售** | 客户拜访、产品演示、商务谈判 | 客户背景、需求、产品反馈、异议、成交结果与跟进。 |
| **FDE** | 客户现场调研、技术方案与实施推进 | 工作流、系统和数据约束、方案假设、交付风险与下一步。 |
| **招聘** | 作为面试官评估候选人 | 经历技能、回答质量、岗位期望与面试结论。 |
| **团队会议** | 周会、项目例会、经营会 | 成员进展、公告、阻塞项、决策与负责人。 |
| **求职** | 作为候选人参加求职面试 | 面试问题与回答、岗位细节、改进点与后续行动。 |
| **技术面试** | 算法、代码、系统设计或白板面试 | 分步推理、边界情况、代码提示与问题覆盖情况。 |
| **讲座** | 课程、培训、分享或内部宣讲 | 主题、核心概念、详细笔记与课后任务。 |

模式不是事实校验器：它会改变组织和提示的重点，但重要报价、合规、交付或业务承诺仍须回到原始资料确认。你可为模式维护自定义上下文、参考文件、笔记分区和意图词；这些内容应只填写本次角色真正需要的资料。

## 5. AI 会前准备

这里的“开始准备”用于某一场会议的背景与资料准备，不是安装后的“初始设置”。

“开始准备”用于把会前已知信息整理成可检查的准备清单。它会创建一条新的空白准备，不会自动打开上一次草稿；既有草稿和完成结果可在“最近准备”中查看。

1. 在启动器中点击“开始准备”。输入或说出会议主题、客户、参会人、目标、议程和已知背景；识别结果可以继续手动修改。
2. 核对拆解后的字段，并让 AI 在销售、FDE、招聘或团队会议中推荐一个主模式。你可选择关联一场历史会议，以回顾上次讨论和待确认承诺。
3. 查看“对方可能问的问题”及资料状态。状态为“资料充分”时会给出可核对的来源；“部分准备”或“资料缺失”表示应补充资料；“检查失败”只是技术错误，应稍后重新检查。
4. 需要补充内容时点击“补充资料”进入资料库。资料索引完成后，回到该问题点击“重新检查”；它只更新所选问题，不会重做整份准备。
5. 确认模式后点击“使用推荐模式开始会议”。此操作只应用已确认的模式，不会把准备结果自动注入后续会议回答。

会前准备不会自动同步 CRM 或日历，也不会替你确认报价、能力、合规或交付承诺。公司调研入口的结果同样不会自动写入这份准备。

## 6. 知识源：资料库与业务系统

CueUp 有两类知识源，目的都是在回答时补充可追溯的事实，但使用方式不同。

### 资料库：上传本地文件

在“设置 → 知识源 → 资料库”上传 PDF、DOCX、Markdown、TXT 或 PPTX。PPTX 需要已配置并选择 QCLOUD API，旧版 `.ppt` 不支持。

上传后，资料先进入索引队列。显示“已完成”前，不能期待它被语义检索引用；失败资料可重新上传或重新索引。Embedding 暂不可用时，界面会明确提示，CueUp 会退回关键词匹配而不是停止检索。

资料库适合产品材料、方案、规范、案例和项目文件。回答只使用检索命中的片段，不表示整份文件已经被验证；涉及金额、合规或责任归属时，仍需打开原始文件核对。

### 业务系统知识源：受控的只读查询

在“设置 → 知识源 → 业务系统知识源”添加系统地址、认证方式与凭据，再先执行连接测试。当前可连接 Windchill（PLM）、QMS 和其他受控业务系统；认证可使用 API Key 或账号密码，保存后的凭据不会在界面回显。

业务系统知识源仅用于读取和检索。CueUp 不会通过它创建、更新、审批或承诺业务动作；所有写入和审批仍应在原系统中由人确认。连接失败时，先检查地址、认证信息和服务端访问权限。

## 7. 开始第一场会议

1. 回到主界面，选择本次会议的模式。
2. 首次设置已就绪时点击“开始会议”，或日常从“启动 CueUp”及已配置的快捷键进入会议。
3. 确认麦克风输入正常后开始会议。
4. 会议进行中，CueUp 会显示滚动转录，并在适当时机给出智能卡片或回答建议。

如果需要根据屏幕内容提供帮助，macOS 在“系统设置 → 隐私与安全性”中检查**录屏与系统录音**（名称随系统版本而异）；全局键盘交互另按需检查**辅助功能**。截图自身仍检查屏幕权限。仅麦克风转写无需屏幕录制权限；系统音频由所选后端在实际采集时检查，CoreAudio 与 ScreenCaptureKit 所需授权可能不同，请按系统提示处理。

首次会议会区分“已进入会议”“音频已启动，等待转写”和“已收到转写”。窗口打开不等于采音或转写成功。用自己的声音和一段可听见的会议声音分别确认输入，实际报错时再按错误提示检查权限、设备或服务。

## 8. AI 会议辅助：会中如何使用

开始会议后，先确认滚动转写持续更新。它是大部分会中能力的输入；音频没有被正常转写时，AI 回答、摘要和动态卡片都可能缺少必要上下文。

### 手动发起问题

在启动器或辅助界面的输入框中直接提问，例如“给我一个澄清问题”“总结刚才的决定”“下一步如何回应客户的集成顾虑”。CueUp 会结合当前输入、最近会议上下文、所选模式及命中的知识源片段生成建议。

需要根据屏幕内容回答时，使用“截图提问”或对应快捷操作。屏幕内容属于单独的数据范围：若未授权屏幕录制权限或未允许云端提供商使用截图，CueUp 不会把截图发送给该提供商。

### 使用实时提示与动态卡片

CueUp 会根据已转写的会议信号、可信证据和当前模式，在界面右侧显示动态卡片。它可能提供：

- 可以直接说出口的回答建议；
- 可核对的检查清单；
- 邮件或跟进草稿；
- 带负责人与截止时间的行动项；
- 带依据的决策记录。

卡片只在满足触发条件时出现，不是每句话都会有。高置信度卡片可能显示约 5 秒倒计时并自动执行；按 `Tab` 可立即接受当前主卡片。界面同时最多显示 3 张，新的高优先级卡片可能替换较旧卡片。接受、忽略或关闭卡片前，请先确认内容符合实际会议和你的表达意图。

### 控制上下文与隐私

在提问前，确认所选模式和可用知识源正确；这比把所有资料都塞进问题更可靠。云端 LLM 的数据范围可分别控制转录、截图、参考资料、档案历史、Embedding 与会后摘要。关闭某项范围时，CueUp 不会将该类数据发送给该提供商。

## 9. 会后查看、搜索与导出

结束会议后，可在“我的 CueUp”中打开记录，查看：

- 会议概述、关键要点、决策、行动项和待确认事项。
- 完整转录及模式相关的跟进建议。
- 对本场或全部会议的问答与全文搜索结果。

导出会议时，导出的 DOCX 以详细会议摘要为主，并可按需要附带完整转录；生成后的 DOCX 可以继续在 Word、WPS 等编辑器中修改。

## 10. 可选：建立“我的声音”

“我的声音”用于识别转录中哪些内容更可能是你本人说的，帮助减少发言归属错误。它不是多人说话人分离的替代品。

录制时请用正常语速连续朗读屏幕提示，尽量少停顿。每段录音最长约 15 秒，系统需要累计至少 8 秒有效语音；录音提前结束而未达标时，请按提示重新录制。

## 常见问题

### 没有转写结果

检查麦克风权限、输入设备和所选语音模型是否已准备完成。本地模型尚未下载完成时，先等待下载和初始化结束。

### 看不到屏幕相关功能

确认已授予屏幕录制权限。macOS 修改权限后，通常需要退出并重新打开 CueUp 才能生效。

### 系统权限已开，但初始设置仍显示“使用时确认”

这是 2.7.22 的被动检查状态，不代表被拒绝。继续配置后，在真实会议中检查系统音频是否采集与转写。若开始会议后出现实际权限错误，再核对系统设置中当前 CueUp、所选采集方式和输出设备，完全退出重开后重试。不要仅凭首次设置状态重置系统权限；移除下载隔离属性也不会授予录音权限。

### 上传资料后无法立即引用

资料正在索引时不能用于语义检索。等待资料库显示“已完成”后，再发起会议问答或搜索。

### 智能卡片没有出现

智能卡片只会在当前模式和会话内容满足触发条件时出现。先确认会议已正常转写、模式选择正确，并查看“设置 → 帮助与设置指南”中的模式说明。

### 云端服务报错

到“设置 → QCLOUD API”或对应服务设置检查连接状态、凭据、余额与数据范围授权。界面会区分鉴权、限流、超时和服务响应异常等常见问题。

## 下一步

完成首次会议后，打开“设置 → 帮助与设置指南”查看各模式、知识源、快捷键、隐私范围和故障排查的完整说明。
