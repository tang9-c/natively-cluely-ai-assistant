# PPTX 内容提取最小可靠性修复设计

日期：2026-08-25

项目：Natively / CueUp

状态：已确认，待制定实施计划

关联设计：`2026-07-07-pptx-rag-design.md`

## 1. 背景与问题

当前 PPTX 内容提取采用既有两阶段流程：

1. 将每一页转换为临时图片；
2. 对每页执行一次视觉内容提取；
3. 对提取结果执行一次文本增强；
4. 所有页面完成后，统一生成知识库分块并写入现有 RAG 索引。

在一份 107 页的有效 PPTX 上，前 72 页已经完成模型调用，第 73 页调用因默认 8 秒超时而失败。当前实现没有隔离单页异常，因此将整份材料标记为解析失败，并向用户显示文件可能损坏。该提示与事实不符：文件结构有效，本地也能够成功转换全部 107 页。

问题的根因不是 PPTX 损坏，而是：

- 单页模型调用失败会终止整份文档处理；
- 云端调用异常被错误归类为文档解析失败；
- 当前允许最多 200 页，导致超长 PPTX 需要执行大量串行模型调用，失败概率和等待时间均过高。

## 2. 设计目标

本次只修复现有方案的可靠性问题，不重做 PPTX 处理架构。

目标：

- 单页模型调用失败不再导致整份 PPTX 失败；
- 成功页面仍能进入现有 RAG 索引；
- 用户能够准确看到材料是否存在缺页；
- 避免 PPTX 页面继续使用不适合文档提取的默认 8 秒调用超时；
- 将单个 PPTX 的处理上限降低到 60 页，控制等待时间和累计失败概率；
- 错误信息准确区分文件损坏、页数超限和模型调用失败。

## 3. 明确不做

本次不实现：

- 逐页持久化；
- 新数据库表或字段；
- 断点续传；
- 后台任务队列；
- 并行页面处理；
- 章节级索引；
- 跨页批量语义增强；
- 整份 PPTX 的额外摘要；
- 失败页面的人工重试界面；
- 修改现有的“视觉提取 + 文本增强”两阶段调用方式。

应用在全部页面处理完之前退出时，仍需从头重新处理。这是保持本次修复简单所接受的限制。

## 4. 页数限制

### 4.1 规则

- 1–60 页：允许处理；
- 61 页及以上：拒绝处理；
- 只调整 `.pptx`，不改变其他材料格式的限制。

页数必须在 PPTX 基础解析完成后、任何模型调用开始前检查，避免产生无效 API 消耗。

### 4.2 用户提示

超过限制时显示：

> 该 PPTX 共 {slideCount} 页，当前单个文件最多处理 60 页。请按章节拆分为多份，每份不超过 60 页后重新上传。

提示必须使用“多份”，不能固定要求拆成“两份”，因为超过 120 页的文件拆成两份后仍可能超限。

该错误使用独立错误码：

```text
pptx_page_limit_exceeded
```

不得将页数超限显示为文件损坏或内容提取失败。

## 5. 单页失败隔离

### 5.1 保留现有处理方式

每页继续执行：

```text
临时图片
  -> 视觉内容提取
  -> 文本增强
  -> 在内存中生成该页的 KnowledgeMaterialChunkInput
```

所有页面处理结束后，继续调用现有的统一索引逻辑。成功页面在处理过程中保存在内存，不增加页级数据库状态。

### 5.2 异常处理

每一页的视觉提取和文本增强必须位于页级异常边界内：

- 页面成功：加入待索引分块集合；
- 页面失败：记录失败页码和安全错误分类，然后继续下一页；
- 页面失败不能向外抛出并终止整个循环；
- 日志不得包含页面正文、提示词、图片路径或图片内容。

PPTX 页面使用以下固定超时预算，不修改所有 LLM 请求共用的默认 8 秒策略：

- 视觉内容提取：单次最多 20 秒；
- 文本增强：单次最多 20 秒；
- 只有文本增强返回了不合法 JSON 时，允许再调用一次，最多 20 秒；
- 视觉提取或文本增强发生超时时不重试，直接将当前页记为失败并继续下一页；
- 单页模型调用的最坏累计等待时间为 60 秒。

JSON 格式错误重试不等同于超时重试。该区分既保留现有的结构化输出修复能力，也避免云端不可用时同一页面被重复阻塞。

### 5.3 文档级结果判定

页面循环结束后：

- 成功页数等于总页数：按现有方式完成索引，状态为“处理完成”；
- 至少一页成功、至少一页失败：只索引成功页，状态显示为“处理完成，但有缺页”；
- 所有页面均失败：材料处理失败，不创建空索引。

失败页面不得生成占位内容，也不得进入 RAG，避免回答引用未经提取的页面。

## 6. 状态与界面

### 6.1 成功状态

全部成功：

```text
处理完成
资料已可用于回答。
```

部分成功：

```text
处理完成，但有缺页 · {successCount}/{slideCount} 页
部分页面内容提取失败，其余页面已可用于回答。
```

例如：

```text
处理完成，但有缺页 · 59/60 页
```

部分成功不能显示为“索引失败”，因为成功页面已经可以被检索。

部分成功继续使用现有材料状态 `complete`，并复用现有字段保存非阻断警告：

```text
status = complete
error_code = pptx_partial_pages
error_message = 处理完成，但有缺页 · {successCount}/{slideCount} 页
```

这里的 `error_code` / `error_message` 只作为现有通用结果字段使用，不表示材料不可用。状态解释层必须先识别 `complete + pptx_partial_pages`，将其渲染为 warning；其他 `complete` 材料仍保持当前成功提示。该做法无需修改数据库结构。

### 6.2 错误分类

至少区分以下文档级结果：

| 情况 | 用户结果 |
| --- | --- |
| 无效 ZIP、PPTX 结构损坏 | 文件损坏或不是有效的 PowerPoint 文件 |
| 超过 60 页 | 页数超限，并提示拆分 |
| 单页模型调用失败，但存在成功页 | 处理完成，但有缺页 |
| 所有页面模型调用均失败 | 内容提取失败，请稍后重试 |
| 页面转换整体失败 | 内容提取失败或文件格式异常 |
| 索引写入失败 | 索引失败，不得伪装成文件损坏 |

云端超时、服务错误或模型输出异常不得映射为“文件损坏”。

## 7. 数据与索引行为

本次沿用现有数据库结构和索引入口：

- 一张成功幻灯片仍对应一个知识分块；
- 分块元数据中的 `slide_index` 和 `slide_count` 保持原始页码及原始总页数；
- 缺页后不得重新连续编号，否则引用页码会与原文件不一致；
- 成功页面处理完后一次性写入现有 RAG 索引；
- 如果最终统一索引失败，材料仍按现有索引错误处理，不能显示为部分成功。

“有缺页”结果通过现有材料的 `status`、`error_code` 和 `error_message` 保存。数据库只持久化成功页数和总页数，不持久化失败页码列表。失败页码只在当前处理过程的内存中用于统计和诊断，不新增数据表或字段。

重新索引基于已经成功提取的分块执行，不能清除 `pptx_partial_pages` 警告。否则重新索引后界面会错误地暗示原始 PPTX 已被完整提取。

## 8. 处理流程

```text
用户上传 PPTX
  -> 校验格式和云端能力
  -> 转换并取得总页数
  -> 页数 > 60：停止并提示拆分
  -> 页数 <= 60：按现有顺序逐页处理
       -> 当前页成功：结果保存在内存
       -> 当前页失败：记录页码并继续
  -> 成功页数 = 0：材料失败
  -> 成功页数 > 0：统一写入现有 RAG 索引
       -> 无失败页：处理完成
       -> 有失败页：处理完成，但有缺页
  -> 清理全部临时文件
```

无论成功、部分成功或失败，临时图片都必须继续在 `finally` 中清理。

## 9. 测试要求

### 9.1 页数限制

- 60 页 PPTX 可以进入模型处理；
- 61 页 PPTX 在首次模型调用前被拒绝；
- 超限提示包含实际页数、60 页限制和“拆分为多份”；
- 超限错误不会显示为文件损坏；
- 超限处理不会产生视觉模型调用。

### 9.2 单页失败

- 中间页视觉调用失败后，后续页面继续处理；
- 中间页文本增强失败后，后续页面继续处理；
- PPTX 视觉提取和文本增强分别使用 20 秒超时，其他 LLM 调用的默认超时不变；
- 只有文本增强 JSON 不合法时允许重试一次，超时不得重试；
- 单页模型调用的累计等待时间不超过 60 秒；
- 部分页面失败时，只为成功页面创建分块；
- 分块保留原始幻灯片页码；
- 部分成功显示正确的成功页数与总页数；
- 部分成功使用 `complete + pptx_partial_pages`，且状态解释为 warning 而不是失败；
- 重新索引部分成功材料后，缺页警告和页数统计仍然保留；
- 全部页面失败时不创建空索引；
- 云端超时不会显示为文件损坏。

### 9.3 回归

- 全部页面成功时，现有 PPTX RAG 行为不变；
- PDF、DOCX、Markdown 和 TXT 上传行为不变；
- 重新索引成功的 PPTX 仍使用现有已提取分块；
- 成功、部分成功和失败路径都会清理临时文件；
- 日志不包含用户页面内容、提示词或临时图片路径。

## 10. 验收标准

- 单个 PPTX 最多处理 60 页；
- 超过 60 页时，在模型调用前给出准确拆分提示；
- 任一单页失败不会终止剩余页面处理；
- 存在成功页面时，这些页面能够进入现有 RAG；
- 部分成功明确显示“处理完成，但有缺页”和页数统计；
- 所有页面失败时不会生成空材料索引；
- 云端调用失败不再被误报为文件损坏；
- 不增加逐页持久化、新数据表、断点续传或新的处理架构。

## 11. 对原设计的覆盖

本设计仅覆盖 `2026-07-07-pptx-rag-design.md` 中以下规则：

- PPTX 页数上限从 200 页调整为 60 页；
- “任一 QCLOUD 内容提取失败则整份材料失败”调整为页级失败隔离；
- 增加“处理完成，但有缺页”的部分成功结果。

原设计中的格式限制、QCLOUD 能力门槛、每页一个分块、临时文件清理、安全日志要求及现有 RAG 结构继续有效。
