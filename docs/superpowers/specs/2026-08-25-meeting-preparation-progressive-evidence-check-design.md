# 会议准备渐进式资料检查设计

## 问题

当前“生成准备结果”在一个请求中串行完成基础问题预测和最多三题的资料证据检查。基础预测和每次证据判断都可能等待选定模型最多 45 秒，因此用户可能在两三分钟内只能看到统一的处理中状态。

本次优化解决首屏等待体验，不承诺缩短全部证据检查完成的总时长。

## 设计决定

- “生成准备结果”只生成并保存基础结果，然后立即进入结果页。
- 无需内部资料的问题在基础结果中直接标记为“无需内部资料”。
- 需要内部资料的问题先保存为“等待检查”，并保留 AI 已生成的资料需求。
- 前端进入结果页后，按照问题顺序串行调用现有 `meetingPreparationRecheckQuestion`。
- 每完成一题，使用接口返回的最新记录更新页面；不新增 IPC 进度事件、后台任务或数据库表。
- 证据检查期间锁定全部问题的新增、编辑、删除和手动重新检查。
- “使用推荐模式开始会议”不受证据检查状态影响，用户可以立即开始会议。
- 用户开始会议或离开准备页后，已经发起的逐题检查继续执行；每次检查结果由现有后端接口即时保存。
- 本期不支持应用退出或重启后的自动恢复；重新打开记录后，未完成问题仍可手动重新检查。

## 数据流

1. 页面调用现有 `meetingPreparationGenerate`。
2. 后端执行一次基础预测，保存历史摘要、承诺和最多三个预测问题，不执行资料 RAG 与证据判断。
3. 后端返回基础记录，页面立即切换到结果步骤。
4. 页面筛选 `evidenceStatus === null` 且没有检查失败标记的问题，并进入自动检查状态。
5. 页面依次调用现有 `meetingPreparationRecheckQuestion`。
6. 后端沿用现有逻辑重新确认资料需求、执行 RAG 和证据判断、保存该题并返回完整记录。
7. 页面逐题接收记录并更新状态，直到全部问题完成或失败。

## 页面状态

- 当前正在调用接口的问题显示“检查中”。
- 尚未调用的问题显示“等待检查”。
- 已完成问题继续使用“资料充分”“部分准备”“资料缺失”或“无需内部资料”。
- 单题接口失败时，将该题持久化标记为“检查失败”，继续处理下一题。
- 自动检查进行期间，问题编辑控件统一锁定。
- 顶部返回调整和其他可能覆盖准备结果的操作继续锁定。
- “使用推荐模式开始会议”单独判断，只在原有同步生成操作期间禁用，不因后台逐题检查禁用。

## 并发与一致性

- 自动检查严格串行，避免触发同一准备记录的 `runExclusive` 冲突。
- 每次接口返回完整最新记录，下一次调用使用稳定的问题 ID，不依赖数组位置。
- 自动检查开始时复制待检查问题 ID 列表；检查期间禁止编辑，避免旧结果覆盖新问题文本。
- 组件卸载后不再更新页面状态，但已发起的 IPC 调用可以完成并保存结果。

## 错误处理

- 基础预测失败时沿用现有错误提示，保留原内容，不进入结果页。
- 单题检查失败不撤销基础准备结果，也不终止后续问题检查。
- 失败题保留问题文本和资料需求，用户稍后可点击“重新检查”。
- 自动检查结束后解除问题编辑锁定。

## 非目标

- 不新增并行证据检查。
- 不新增后台任务队列、断点恢复或跨重启恢复。
- 不新增 IPC 推送事件。
- 不调整选定模型、45 秒单次超时或供应商降级策略。
- 不改变 AI 自动预测最多三个问题、用户手动添加不限数量的现有边界。

## 测试

- 服务测试证明基础生成不再调用资料检索或证据覆盖 LLM。
- 服务测试证明基础生成仍保存最多三个问题及其资料需求。
- UI 契约测试证明基础记录返回后先进入结果页，再启动逐题检查。
- UI 测试证明问题检查严格串行并逐题接受最新记录。
- UI 测试证明自动检查期间问题编辑被锁定，但开始会议按钮不被锁定。
- UI 测试证明单题失败被标记后继续下一题。
- 现有逐题重新检查、AI 三题上限和手动问题不限量测试继续通过。

## 验收标准

- 基础预测完成后立即显示结果页，不等待任何资料 RAG 或证据覆盖判断。
- 每个待检查问题的状态随后逐题更新。
- 用户在证据检查未完成时可以开始会议。
- 检查期间不能修改问题。
- 单题失败不影响其他问题和已生成的基础结果。
