# 全局会议搜索中文召回修复设计

日期：2026-08-13

## 问题与证据

用户提供的完整会议转录中，“数字化移交”出现 3 次，“手术机器人”出现 3 次，“机器人”出现 16 次；但全局会议搜索只有“机器人”返回了相关事实。该问题不是原文缺失，而是检索链路存在三个独立缺陷：

1. `buildRetrievalQuery()` 会追加 `intent:open_question`，`searchLexicalMeetings()` 又只取分词结果的第一个词；由于英文词先于中文词，SQL 实际搜索 `intent`，没有搜索用户原词。
2. 混合排序将纯词法命中缩放到 40%，再叠加 30% 的新近度权重。旧会议中的精确命中可能被近期、仅达到最低向量相似度的弱候选挤出 Top-K。
3. `preprocessTranscript()` 用空格统计“单词”，少于 3 个就删除。没有空格的有效中文句子会在未与相邻段合并时丢失。

## 目标与非目标

目标：

- 全局会议搜索的原始转录兜底必须使用原始用户问题，而不是带检索元数据的扩展查询。
- 包含用户完整查询词的词法候选必须进入最终上下文，不得被新近度或弱语义候选淘汰。
- 有意义的中文段落不能因为没有空格而被删除。
- “数字化移交”“手术机器人”“机器人”均有自动化回归覆盖。
- Embedding 不可用或会议没有可用分块时，原始 `transcripts` 仍可完成精确词法召回。

非目标：

- 不重写向量检索、Embedding provider 或数据库 schema。
- 不改变全局搜索 UI、答案提示词或引用格式。
- 不为所有语言引入新的分词依赖。
- 不自动修改用户已有会议原文。

## 方案选择

### 方案 A：提高 Top-K 或降低相似度阈值

改动最少，但无法修复 SQL 搜索 `intent`、中文段落被删除以及旧会议精确结果被时间权重压制的问题。拒绝。

### 方案 B：只使用词法搜索

精确查询可靠，但会损失同义表达和语义召回。与现有混合检索产品目标不符。拒绝。

### 方案 C：分离原始查询与扩展查询，并保留精确词法席位

保留现有语义能力，同时修复三个确定性缺陷，改动集中在 RAG 检索和转录预处理。采用此方案。

## 详细设计

### 1. 查询职责分离

`retrieveGlobal()` 保留两份查询：

- `query`：未经扩展的用户原始问题，用于会议标题、摘要和原始转录 SQL 兜底，也用于判断完整词组是否精确命中。
- `retrievalQuery`：可包含 intent 和近期上下文，用于 Embedding 查询以及宽松的分块词法评分。

`searchLexicalMeetings()` 接收原始 `query`。它不得依赖 `intent:*` 等内部元数据。SQL 的候选词应优先使用用户原始查询中的有效完整词组；若需要短词回退，应只从原始查询分词中选取，不读取扩展字段。

### 2. 精确词法候选保留

混合候选排序前标记包含规范化原始查询完整字符串的候选。最终选择上下文时：

- 先保留可放入 token 预算的精确词法候选，数量受现有 `topK` 和预算限制。
- 再按现有混合相关度与新近度填充剩余席位。
- 精确候选内部仍可按相关度和时间排序，但新近度不能让不包含查询词的弱候选越过精确候选。
- 若精确候选本身大于总 token 预算，不把超大块强塞给 LLM；原始会议兜底应提供较小的匹配转录证据。

这保持现有语义检索能力，同时建立“精确文本命中优先”的最低正确性保证。

### 3. 中文有效内容判断

转录预处理不再仅用空格词数判断内容长度：

- 包含 CJK 字符时，以去除空白和标点后的 CJK/字母数字字符数判断。
- 至少 2 个有效 CJK 字符视为可索引内容。
- 非 CJK 内容继续沿用至少 3 个空格分隔词的现有规则。
- 纯填充词、确认词和空文本仍应被过滤。

该规则不引入第三方分词器，也不改变后续分块参数。

## 数据流

```text
用户问题
  ├─ 原始 query ────────────────┐
  │                             ├─ 标题/摘要/原始 transcript 兜底
  │                             └─ 精确词法候选判定与保留
  └─ 扩展 retrievalQuery
        ├─ Embedding 查询
        └─ 分块宽松词法评分

两路候选合并 → 精确候选优先 → 相关度/新近度填充 → token 预算 → LLM
```

## 错误与降级

- Embedding 查询失败时，全局搜索继续执行词法分块与原始会议兜底，不应提前返回空上下文。
- 没有精确词法结果时，保持现有语义排序行为。
- 原始转录兜底只返回匹配记录及必要会议元数据，不扩大为整场会议，避免超出 token 预算。
- 日志只记录候选数量、查询是否含有效词及降级类型，不记录查询或会议原文。

## 测试设计

按 TDD 分三组建立先失败后通过的行为测试：

1. `TranscriptPreprocessor`：无空格的有效中文句子被保留；单字符和空白仍被过滤；英文短句规则不回退。
2. `VectorStore.searchLexicalMeetings()`：扩展查询中存在 `intent:*` 时，SQL 仍以原始中文查询命中仅存在于 `transcripts` 的会议；测试真实 SQLite 行为，不做源码正则断言。
3. `RAGRetriever.retrieveGlobal()`：旧会议精确词法候选与多个近期弱向量候选竞争时，精确候选仍进入最终上下文；Embedding 失败时词法路径仍可返回结果。
4. 使用用户转录中的脱敏最小片段覆盖“数字化移交”“手术机器人”“机器人”三个查询，断言每个查询均返回包含目标词的证据，不把完整原文提交到仓库。

验证顺序：定向测试、Electron 类型检查、完整 `npm test`。最后增量更新代码图谱并确认工作区只包含本任务文件和用户原有 `.tmp/`。

## 成功标准

- 三个中文查询均能从仅有原始转录或旧会议分块的测试数据中召回正确证据。
- 精确旧会议候选不会被近期最低相似度候选淘汰。
- 中文有效句子进入分块，英文和噪声过滤行为保持兼容。
- 定向测试、类型检查和完整测试全部通过。
