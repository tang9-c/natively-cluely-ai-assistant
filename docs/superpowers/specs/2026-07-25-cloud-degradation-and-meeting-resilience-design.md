# 云端降级提示与会议处理韧性设计

## 目标

修复三个相互关联但边界独立的问题：

1. 会议标题生成失败时，结构化摘要和会后增强仍继续执行。
2. 销售模式的云端语义门控不可用时，用户能清楚看到降级状态，而不是只在日志中记录。
3. 打包后的本地意图分类器 worker 能可靠加载 `onnxruntime-node`。

普通转录、会议保存、现有高风险语义门控策略和 provider 路由保持不变。

## 会议标题与摘要隔离

标题生成使用独立的 `try/catch`。标题请求失败时：

- 记录不包含转录内容的警告。
- 保留现有后备标题 `Untitled Session`。
- 继续加载模式分区、生成结构化摘要和执行会后增强。

摘要及增强仍保留现有外层异常边界，确保任何后处理失败都不会阻止会议最终保存。

## 动态卡片云端降级提示

销售模式的高风险卡片继续要求云端语义确认，不扩大本地自动放行范围。已有明确短语规则允许的本地降级保持不变。

当动态动作语义门控产生以下状态时，主进程向 launcher 和 overlay 发送独立状态事件：

- `cloud_unavailable`：云端不可用，高风险卡片已暂缓。
- `local_fallback_cloud_unavailable`：云端不可用，当前信号已使用受限本地判断。
- `cloud_used`：云端恢复，清除降级提示。

事件只包含状态、标准化原因和时间戳，不包含转录、匹配证据、prompt 或 provider 错误正文。

renderer 在动态卡片区域显示紧凑状态提示：

- 云端不可用：`云端服务繁忙，智能卡片暂不可用`
- 补充行动说明：`会议与转录继续正常，服务恢复后将自动重试`
- 本地受限判断：`云端服务繁忙，部分明确提示已切换为受限本地判断`

提示应满足：

- 同一状态重复到达时不叠加。
- 云端恢复后自动清除。
- 长时间没有新状态时自动过期，避免旧故障一直显示。
- 不提供“强制生成”入口，避免绕过高风险门控。

## 本地分类器模块加载

移除 worker 中通过 `new Function()` 访问 `require` 的方式。Electron main 使用 CommonJS 构建，因此 worker 直接使用模块作用域的 `require` 加载：

- `onnxruntime-node`
- `onnxruntime-node/package.json`

这保留现有 preflight、版本提示和原生能力检查，同时避免打包运行时的 `require is not defined`。

## 测试

新增或更新以下回归覆盖：

- 标题生成抛错后，摘要生成仍被调用并持久化。
- 云端语义门控失败时不生成未经确认的高风险销售卡片，但会产生可转发的降级状态。
- 主进程只转发脱敏状态字段。
- renderer 显示云端不可用、本地受限判断和恢复后的状态变化。
- worker preflight 不再使用 `new Function(...require...)`，并在打包式 CommonJS worker 环境中完成模块加载。

运行针对性的 Electron 测试、renderer 契约测试、Electron 类型检查和 renderer TypeScript 检查。

## 非目标

- 不修改 QCLOUD 模型选择或服务端容量策略。
- 不新增未经云端确认的高风险销售建议。
- 不把 provider 原始错误、CPU 百分比或转录内容展示给用户。
- 不改变 STT、会议转录保存或 RAG 行为。
