# 会议准备信息拆解提示词强化设计

## 背景

会议准备页面调用大模型拆解用户输入时，实际模型输出中的 `participants`、`agenda`、`background` 字段类型不符合现有 Zod 结构，导致操作失败。当前数据库、IPC 和页面状态保留机制均正常，问题限定在模型输出契约不够明确。

## 目标

通过强化拆解提示词，降低模型返回错误字段类型的概率，使当前失败输入能够进入“确认信息与模式”步骤。

## 方案

只修改会议准备信息拆解提示词：

- 给出完整 JSON 字段结构，不再只列字段名。
- 明确 `topic`、`customer`、`goal` 为 `{ value, state }` 对象。
- 明确 `participants` 为 `{ name, role }` 对象数组。
- 明确 `agenda` 为字符串数组。
- 明确 `background` 为字符串。
- 列出 `state` 的允许值，并要求不确定字段使用 `needs_confirmation`。
- 提供一个合法 JSON 示例，要求只返回 JSON，不添加解释或 Markdown 代码块。

不增加模型输出归一化或宽松类型转换，不修改数据库、IPC、页面流程和供应商路由。

## 错误处理与隐私

现有校验和失败行为保持不变：模型输出不满足结构时拒绝结果，保留用户原始输入，并提示用户重试。保留仅包含错误类型、字段路径和校验错误码的安全诊断日志；不得记录用户输入、模型原文或会议内容。

## 测试与验收

- 增加提示词契约测试，验证提示词包含完整结构、关键字段类型和合法示例。
- 运行会议准备相关定向测试与 Electron 类型检查。
- 在本地 Electron 中使用已复现失败的输入重新执行拆解，确认能够进入“确认信息与模式”步骤。
- 若实际供应商仍违反类型契约，本方案不自动转换结果，继续使用现有失败处理。

## 已知限制

提示词约束不是强制结构化输出，无法保证所有模型和所有输入都返回正确类型。本设计接受这一限制，以换取最小改动范围；若失败持续发生，再单独评估保守归一化或供应商原生结构化输出。
