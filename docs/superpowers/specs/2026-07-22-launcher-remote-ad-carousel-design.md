# 启动窗口远程广告轮播设计

**日期：** 2026-07-22  
**状态：** 已批准  
**范围：** 将启动窗口右侧占位卡片改为远程图片广告轮播

## 1. 背景与目标

`src/components/Launcher.tsx` 的 Hero 区域包含一张右侧占位卡片，目前只显示 `CueUp / AI Meeting Assistant`，卡片下半部为空。该区域将改造成广告位，用于轮播：

- CueUp 核心能力
- CueUp 新功能
- CueUp 使用技巧
- 其他产品广告

广告素材采用纯图片形式。客户端不在图片上叠加标题、按钮或品牌文案。广告列表由远程 JSON 配置控制，更新广告不需要发布客户端新版本。

## 2. 已确认的产品决策

- 视觉形式：纯远程图片素材
- 配置来源：远程 JSON
- 点击行为：通过系统默认浏览器打开外部链接
- 轮播方式：每 6 秒自动轮播、底部圆点切换、悬停暂停
- 失败回退：显示应用内置 CueUp 默认广告图
- 第一版不采集曝光、点击或用户定向数据
- 第一版不建设广告管理后台

## 3. 架构

### 3.1 `RemoteAdService`（Electron 主进程）

负责：

- 请求远程广告 JSON
- 校验响应结构和字段
- 过滤不安全、无效或过期的广告
- 按优先级排序并限制返回数量
- 缓存最近一次有效配置
- 远程配置不可用时降级到缓存或内置广告

不负责：

- Renderer 轮播状态
- 图片动画
- 曝光或点击统计

### 3.2 广告 IPC

新增两个有限接口：

- `get-launcher-ads`：获取经过主进程校验的广告列表
- `open-ad-link`：重新校验 URL 后，通过 Electron `shell.openExternal()` 打开

接口通过 `electron/preload.ts` 暴露，并同步更新 Renderer 的 Electron API 类型。Renderer 不直接请求远程配置，也不直接访问 Electron `shell`。

IPC handler 使用项目现有的 `safeHandle()` 注册方式。

### 3.3 `LauncherAdCarousel`（Renderer）

新增独立组件，避免继续扩大接近 1000 行的 `Launcher.tsx`。组件负责：

- 获取广告列表
- 图片预加载与失败追踪
- 自动轮播
- 圆点手动切换
- 悬停暂停
- 可访问性与点击交互
- 全部远程图片失败时切换至内置广告

`Launcher.tsx` 只负责把该组件放入现有右侧卡片位置。

## 4. 远程配置协议

### 4.1 JSON 示例

```json
{
  "version": 1,
  "ads": [
    {
      "id": "cueup-post-call-2026-07",
      "imageUrl": "https://cdn.example.com/ads/post-call.webp",
      "targetUrl": "https://example.com/features/post-call",
      "alt": "CueUp 会后总结",
      "startsAt": "2026-07-01T00:00:00Z",
      "endsAt": "2026-08-01T00:00:00Z",
      "priority": 100
    }
  ]
}
```

### 4.2 字段规则

| 字段 | 必填 | 规则 |
|---|---:|---|
| `version` | 是 | 第一版只接受 `1` |
| `ads` | 是 | 数组，处理后最多返回 10 项 |
| `id` | 是 | 非空字符串，在当前配置中唯一 |
| `imageUrl` | 是 | 只接受有效的 `https:` URL |
| `targetUrl` | 否 | 存在时只接受有效的 `https:` URL |
| `alt` | 是 | 非空字符串，用于图片替代文本 |
| `startsAt` | 否 | 有效 ISO 8601 时间；尚未开始时不展示 |
| `endsAt` | 否 | 有效 ISO 8601 时间；到期后不展示 |
| `priority` | 否 | 有限数值，数值越大排序越靠前；缺省为 0 |

远程配置地址由应用构建配置提供。广告 JSON 无权再次指定配置源。

## 5. 视觉与交互

### 5.1 卡片表现

- 保留现有 Hero 网格、卡片尺寸和圆角
- 图片铺满整个卡片，使用 `object-fit: cover`
- 不叠加客户端标题、按钮或品牌文案
- 有 `targetUrl` 时显示可点击状态；无链接时仅展示
- 广告标识如有需要，由图片素材自身包含

### 5.2 轮播行为

- 多张广告时，每 6 秒切换下一张
- 使用淡入淡出过渡，不使用横向滑动
- 鼠标悬停暂停；移出后重新开始完整 6 秒周期
- 底部居中显示分页圆点
- 当前项显示较长的高亮胶囊，其他项显示弱化圆点
- 点击圆点立即切换并重置计时，不触发广告外链
- 单张广告不显示圆点，也不创建轮播定时器
- 尊重 `prefers-reduced-motion`，减少动态效果时取消过渡

### 5.3 点击与键盘

- 有链接的广告支持鼠标点击
- 有链接的广告可获得键盘焦点，并支持 Enter 和 Space 打开
- 无链接的广告不表现为按钮
- 所有跳转均通过 `open-ad-link`，在系统默认浏览器打开
- 不在 Electron 窗口中嵌入第三方网页

### 5.4 素材规范

- 优先 WebP，同时接受 PNG 和 JPEG
- 不接受远程 SVG，避免主动内容风险
- 建议宽度至少为实际显示宽度的 2 倍，以适配 Retina 屏
- 单张建议不超过 500 KB
- 重要文字和主体需保留安全边距
- 不建议 GIF；动态效果由客户端完成
- 图片源需返回正确的图片 MIME 类型

## 6. 数据流与缓存

### 6.1 启动流程

1. `LauncherAdCarousel` 挂载并请求广告列表。
2. `RemoteAdService` 检查本地缓存。
3. 未过期缓存可直接返回，避免阻塞界面。
4. 无缓存或缓存需要刷新时，请求远程 JSON，超时为 5 秒。
5. 服务校验、过滤和排序后写入缓存并返回。
6. Renderer 先预加载第一张图片，再按顺序预加载其余图片。
7. 广告流程异步执行，不阻塞启动按钮或会议历史。

### 6.2 缓存策略

- 缓存保存经过校验的广告配置，不主动下载或持久化图片文件
- 缓存位于 Electron `userData` 目录，不使用 renderer `localStorage`
- 缓存刷新间隔为 1 小时
- 远程请求失败时，可继续使用最近一次有效缓存
- 即使使用旧缓存，`endsAt` 已过期的广告也必须重新过滤
- 不持久化当前轮播位置；应用重启后从第一张开始

## 7. 降级与错误处理

广告来源的降级顺序：

1. 远程最新有效广告
2. 最近一次缓存中的有效广告
3. 应用内置 CueUp 默认广告

单张图片加载失败时：

- 将该广告标记为不可用并切换到下一张
- 不展示破图图标或技术错误文本
- 所有远程图片均失败时展示内置默认广告
- 默认广告使用相同尺寸，避免页面重排

远程请求还应设置合理的响应体大小上限，并拒绝非 JSON 响应和异常 HTTP 状态。广告功能的任何失败都不得影响启动窗口其他功能。

## 8. 安全与隐私

- 配置、图片和跳转 URL 只允许 `https:`
- 主进程在打开链接前再次解析和校验协议
- 拒绝 `http:`、`file:`、`javascript:`、`data:` 等协议
- 远程内容只作为 JSON 数据和 `<img>` 图片处理
- 不执行远程 HTML、JavaScript 或 CSS
- 不加载远程 SVG
- 日志只记录广告 ID、HTTP 状态和失败类型
- 可能包含查询参数的完整 URL 不写入日志
- 所有相关日志遵循项目 `redactForLog()` 规则
- 第一版不采集曝光、点击、用户身份、设备标识或会议数据

## 9. 测试方案

### 9.1 主进程服务测试

验证：

- 有效配置可正确解析和按 `priority` 排序
- 缺少必填字段、重复 ID、非 HTTPS URL、无效日期被过滤
- 尚未开始和已经结束的广告不展示
- 返回数量最多为 10
- 请求成功后写入有效缓存
- 请求失败时使用最近一次有效缓存
- 缓存中的过期广告会再次过滤
- 无可用缓存时返回内置广告
- 超时、非 JSON、超大响应和异常状态码不会抛到启动页

### 9.2 Renderer 组件测试

验证：

- 单张广告不启动轮播、不显示圆点
- 多张广告每 6 秒切换
- 悬停暂停，移出恢复完整周期
- 点击圆点切换并重置计时
- 圆点点击不打开外链
- 单张图片失败会跳过
- 全部远程图片失败会显示默认广告
- 有链接广告支持鼠标、Enter 和 Space
- 无链接广告不可点击
- 卸载组件时清理定时器
- 减少动态效果偏好下不执行淡入淡出

### 9.3 IPC 测试

验证：

- `get-launcher-ads` 只返回服务层校验后的数据
- `open-ad-link` 只接受 HTTPS URL
- preload 暴露接口、类型声明和 handler 保持一致

## 10. 验收标准

- 启动页右侧卡片能够显示远程纯图片广告
- 修改远程 JSON 后，客户端无需发版即可在缓存刷新后显示新广告
- 多张广告每 6 秒自动淡入淡出轮播
- 用户可通过底部圆点切换，悬停时自动轮播暂停
- 点击广告只在系统默认浏览器打开经过校验的 HTTPS 链接
- 离线、配置错误、图片失效时始终显示可用的 CueUp 默认广告
- 广告功能失败不会延迟或阻断启动 CueUp、会议历史等现有功能
- 第一版不产生曝光、点击或用户定向数据

## 11. 非目标

第一版不包含：

- 广告上传或管理后台
- 曝光、点击率或转化统计
- 用户画像或定向投放
- 地域、语言或客户端版本灰度
- 加权随机算法
- 动态 HTML 广告
- 应用内第三方网页浏览器
