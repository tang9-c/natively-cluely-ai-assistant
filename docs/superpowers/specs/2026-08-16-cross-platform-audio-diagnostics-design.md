# 跨平台音频丢样监测与参数合同设计

## 目标

在不修改现有采样率、环形缓冲区容量或 VAD 数值的前提下，让 macOS 与 Windows 音频采集链路能够准确暴露环形缓冲区溢出，并通过自动化测试锁定 SenseVoice 的跨平台输入合同。

## 范围

本次只包含：

- 麦克风和系统音频生产者的真实丢样计数。
- 普通日志中的非零丢样告警。
- 详细日志中的采样率、后端、chunk cadence、VAD 配置和累计丢样统计。
- macOS CoreAudio、macOS ScreenCaptureKit、Windows WASAPI 与 SenseVoice 输入参数的合同测试。

本次不包含：

- 调整任何 buffer 容量。
- 调整采样率、DSP 帧长、批量大小或 VAD 阈值。
- 新增数据库字段、遥测上传或用户界面。
- 记录 PCM、转录文本、设备标识或其他用户内容。

## 方案比较

### 方案 A：原生真实计数，推荐并采用

每个原生音频生产者根据 `push_slice` 或 `try_push` 的实际返回结果累计未写入样本数。计数器使用原子变量，不在实时音频回调中执行日志或 IPC。Electron 侧周期读取计数并负责日志策略。

优点是能准确区分“真正丢样”和“JS 消费延迟”，不会破坏实时线程；代价是需要为各原生后端增加统一的只读诊断接口。

### 方案 B：在 JS 层根据 chunk 间隔推测

实现简单，但无法区分系统静音、操作系统没有回调、原生 buffer 溢出和 Electron 调度延迟，不能作为修复依据，因此不采用。

### 方案 C：直接扩大 Windows buffer

可能降低短时溢出的概率，但没有证据证明当前容量不足，也会掩盖生产者和消费者失衡问题，因此不采用。

## 设计

### 原生计数

麦克风、CoreAudio、ScreenCaptureKit 和 WASAPI 后端各自持有共享原子计数器：

- `droppedSamples`：环形缓冲区没有接收的样本总数。
- `dropEvents`：至少丢失一个样本的写入次数。

生产者回调只进行差值计算和原子累加。计数器从一次 capture 实例创建起单调递增，停止或销毁 capture 时自然释放。

Rust 的 `MicrophoneCapture` 与 `SystemAudioCapture` 暴露只读诊断快照。接口不返回设备名称，不修改现有音频数据回调。

### Electron 日志策略

`MicrophoneCapture.ts` 和 `SystemAudioCapture.ts` 在采集期间以低频定时器读取诊断快照：

- 自上次检查新增丢样时，始终输出一条固定结构的告警。
- 没有丢样时，普通日志不增加周期输出。
- 开启详细日志时，额外输出后端、原生/输出采样率、chunk 数量、平均和最大 chunk 间隔、累计字节数、丢样总数及当前 SenseVoice 通道配置。
- 日志不包含 PCM、Base64、设备 ID、转录、提示词或认证信息。

采集停止、重配设备或应用退出时必须清理诊断定时器并清空会话统计，避免跨会议累计。

### 参数合同

测试锁定以下事实，但不要求底层设备参数相同：

- 正常重采样路径向 STT 输出 16kHz mono PCM16。
- DSP 帧为 20ms；16kHz 时每帧 320 samples；每次最多合并 3 帧。
- SenseVoice Worker 固定接受 16kHz。
- SenseVoice VAD 使用 30ms/480-sample 窗口；系统通道 RMS 阈值为 0.004，麦克风通道为 0.008；两者 hangover 为 30 帧、最短语音为 4 帧。
- CoreAudio 使用低振幅系统音频门控；ScreenCaptureKit 与 WASAPI 使用通用系统音频门控。
- 采样率转换失败时，上报采样率必须与实际透传 PCM 一致。

## 错误处理

- 诊断读取失败只记录固定错误类别，不中断音频或 STT。
- 计数器溢出使用饱和式累计或等价安全处理，不能 panic。
- 详细日志关闭时，不执行高成本统计或格式化。
- 诊断接口不存在时保持兼容，视为“诊断不可用”，不能阻止会议开始。

## 验证

- 单元测试证明部分写入和单样本写入失败会产生正确计数。
- 合同测试覆盖四种采集后端和 SenseVoice 参数。
- 生命周期测试证明停止后诊断定时器被清理，重新启动不会继承旧会话统计。
- 日志测试证明非零丢样始终告警，完整统计只在详细日志开启时输出，且不包含用户内容字段。
- 运行原生相关测试、Electron 类型检查、生产构建、完整 `npm test` 与 `git diff --check`。

## 成功标准

发布后可以仅凭脱敏日志回答“是否发生过原生环形缓冲区溢出、发生在哪个通道和后端、累计丢失多少样本”，同时不改变当前音频质量、延迟和 VAD 行为。
