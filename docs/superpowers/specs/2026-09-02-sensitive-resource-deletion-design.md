# 敏感资料可靠删除设计

## 目标

用户删除简历、JD、资料库文件、参考资料或模式后，不再保留该对象拥有的原始副本、正文、解析元数据、RAG 分块或 Embedding 队列记录；删除失败不得返回成功。

## 已确认边界

- 简历和 JD 当前会复制到 `profile-uploads`，但成功解析后没有任何代码再次读取这些副本。因此停止创建新副本，并在删除时清理旧版本留下的受控文件。
- 模式参考资料只保存在 SQLite，不产生文件副本。
- 资料库上传不复制原文件，只保存资料记录、分块和 Embedding 队列。
- 当前 `better-sqlite3` 构建默认启用外键，但应用仍应显式启用并验证，避免平台或构建配置改变。
- 文件系统与 SQLite 不能组成真正的原子事务。档案删除先清理受控文件，再清数据库；任一步失败都返回失败。

## 设计

### 档案文件

`ProfileOrchestrator.ingestDocument()` 直接解析用户选择的源文件，不再复制到 `profile-uploads`。`deleteDocumentsByType()` 在专用目录内仅匹配应用生成的 `resume-<timestamp>.<ext>` 或 `jd-<timestamp>.<ext>` 文件，删除并验证后再清除对应数据库内容。目录外文件和不匹配文件绝不触碰。

### 数据库外键与显式清理

数据库连接建立后执行 `PRAGMA foreign_keys = ON` 并读取状态验证；无法启用时初始化失败。模式和参考资料删除仍在单个 SQLite 事务中显式删除子记录，再删除父记录，因此即使测试主动关闭外键也不会残留；外键作为第二层约束。

模式删除覆盖 `mode_reference_file_metadata`、`mode_reference_files`、`mode_note_sections` 和 `mode_intent_keywords`。参考资料删除覆盖 metadata 和正文记录。

### 资料库删除

沿用现有取消集合阻止正在进行的索引继续写入，在事务中删除 Embedding 队列、RAG chunks 和 `knowledge_materials` 父记录。删除 IPC 继续使现有上下文缓存失效。

### 结果与错误

数据库删除方法不再吞掉异常，返回固定字段的删除计数。IPC 仅在操作完整结束后返回 `success: true` 和删除统计；异常返回 `success: false`。日志不得包含文件正文、路径、文件名或认证信息。

## 测试

- 成功上传简历/JD 不产生新的内部副本。
- 删除档案清除同类型旧副本并保留另一类型及无关文件。
- 数据库连接的 `foreign_keys` 必须为 1。
- 即使测试关闭外键，删除参考资料或模式也不留下正文、metadata、分区或关键词。
- 删除资料库文件后，父记录、分块和队列均为零。
- 数据库或文件删除失败时，上层不得报告成功。
- 运行专项测试、Electron 类型检查、生产构建、完整 `npm test` 和 `git diff --check`。

## 非目标

- 不新增数据库路径字段或上传资源清单表。
- 不删除用户选择的源文件。
- 不修改 UI、数据库中与目标资料无关的缓存，也不进行全局目录扫描。
