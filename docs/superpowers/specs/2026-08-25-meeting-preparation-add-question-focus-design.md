# 会议准备新增问题自动定位设计

## 问题

“添加问题”会在问题列表末尾创建空白问题，但页面保持原位置。列表较长时，新输入框可能位于视口之外，用户无法确认操作是否成功，也不能立即开始输入。

仅滚动到新问题仍不够明确：用户还需要再次点击输入框。因此本次交互应同时完成定位和聚焦。

## 设计决定

用户点击“添加问题”后：

1. 在问题列表末尾新增一个空白问题；
2. 页面平滑滚动，使新问题输入框进入视口中央附近；
3. 新问题输入框自动获得焦点，用户可以直接输入；
4. 不增加提示消息、弹窗或新的操作步骤。

## 技术设计

在 `MeetingPreparationPage` 内维护一个仅用于本次渲染的待聚焦问题 ID：

- 点击“添加问题”时先生成新问题 ID，并记录为待聚焦目标；
- 继续沿用现有 `updateRecord`，把空白问题追加到 `questions`；
- 新问题的 `textarea` 挂载时，通过回调 ref 比对问题 ID；
- 命中后先调用 `focus({ preventScroll: true })`，再调用 `scrollIntoView({ behavior: 'smooth', block: 'center' })`；
- 完成后立即清除待聚焦 ID，避免后续渲染重复滚动或抢夺焦点。

该实现不使用定时器，不修改问题数据结构，也不改变现有保存逻辑。

## 边界情况

- 证据检查期间按钮仍按现有规则禁用，不改变锁定行为；
- 只有本次手动新增的问题会触发自动定位，加载历史问题或其他状态更新不会抢夺焦点；
- 如果组件在新输入框挂载前卸载，待聚焦目标随组件销毁，不产生额外副作用；
- 删除、编辑和重新检查问题的行为保持不变。

## 验证方案

增加端到端测试，验证：

1. 进入准备结果页并等待“添加问题”可用；
2. 点击“添加问题”；
3. 新问题输入框已经获得焦点；
4. 新问题输入框位于当前视口内；
5. 无需再次点击即可输入并显示文本。

测试应先在现有实现上失败，再实施最小代码修改使其通过。

## 非目标

- 不改变问题数量限制；
- 不增加 Toast、动画高亮或“已添加”状态；
- 不调整问题生成、RAG 检查、数据库或 IPC；
- 不重构问题列表组件。

## 验收标准

点击“添加问题”后，用户能够立即看到新问题输入框，并直接键入内容；现有问题编辑、删除、证据检查和保存流程无回归。
